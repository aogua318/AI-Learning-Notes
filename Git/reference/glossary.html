Git 术语表

课程里统一采用「英文术语 + 中文解释」的写法：命令、分支名、报错信息保留英文原文，解释用中文。这张表是四节课的词汇底座——读到不熟的词，先回这里对齐，再回去看课。

最常用的八条

git status -sb 定位自己

git log --oneline --graph --all 看历史

git fetch origin 刷新地图

git pull --rebase 重放本地提交

git push -u origin main 首次推送

git switch -c <分支> 建分支

git branch -vv 看跟踪关系

git reflog 找回丢失提交

三条铁律

不改写别人可能基于其工作的历史。

强推只用于自己独占的分支。

动手前先 fetch，再 log。

1. 对象与指针

英文中文一句话解释
repository 仓库 包含全部历史与对象的数据库；本地 .git/ 和 GitHub 上的远程仓库都是完整仓库。 见 0002
commit 提交 一个存档点：快照树 + 父提交 + 作者/时间 + 说明，整体算出一个哈希。 见 0001
snapshot 快照 某个 commit 记录的项目全貌；没变的文件复用上一份内容，不重复存。 Git 的核心心智模型
tree 树对象 目录结构：记录文件名、权限，以及指向子目录或文件内容的引用。
blob 数据对象 文件内容本身（不含文件名），按内容哈希存储。
hash 哈希 / 摘要 由对象内容算出的 40 位十六进制 ID；内容变则哈希变，常用前 7 位。 也是 rebase 后「哈希全变」的原因
parent commit 父提交 当前提交的上一个提交；根提交没有父提交，merge commit 有两个或更多。 见 0004
branch 分支 指向某个 commit 的可移动指针；创建分支不复制文件。 见 0001
main 主干 默认分支名，没有特殊魔力；只是团队约定俗成的主线。 旧仓库可能叫 master
HEAD 头指针 「你现在站在哪」：通常指向当前分支，也可以直接指向某个 commit。 见 0001
detached HEAD 分离头指针 HEAD 直接指向 commit 而非分支；此时新提交没有分支保着，切走易丢。 用 git switch -c <名字> 保下来
ref / reference 引用 指向 commit 的名字，分支、标签、远程跟踪分支都是引用。
reflog 引用日志 HEAD 与分支最近移动过的本地记录；找回「丢掉」的提交的第一站。 git reflog
tag 标签 固定指向某个 commit 的引用，常用于标记版本（如 v1.0）。

2. 三个区域与文件状态

英文中文一句话解释
working tree 工作区 你正在编辑、能直接打开的文件；git status 的第二列反映它。 见 0002
index / staging area 暂存区 下一次 commit 的内容清单；git add 把工作区当前内容登记进来。 不是「把文件加入 Git」
local repository 本地仓库 .git/ 里的完整历史；git commit 把暂存区写成一个新提交。
untracked 未跟踪 新文件，Git 还没纳入版本管理；git add 后变为已暂存。
modified 已修改 工作区内容与暂存区/最新提交不同；git status 显示为  M。
staged 已暂存 改动已登记进暂存区，等待下一次 commit；git status 显示为 M 。
committed 已提交 内容已写入本地仓库，形成一个不可变的提交对象。
.gitignore 忽略规则 告诉 Git 哪些文件不纳入版本管理，如虚拟环境、构建产物、密钥文件。

3. 远程与同步

英文中文一句话解释
remote 远程仓库 另一个完整仓库，通常托管在 GitHub；用昵称 + URL 配置。 git remote -v
origin 远程昵称 clone 时给远程起的默认名字，不是 GitHub 专属，可以改。 见 0002
origin/main 远程跟踪分支 本地缓存的「上次同步时远程 main 的位置」；不是远程本体，不会自动更新。 只有 fetch/pull/push 才刷新
clone 克隆 把远程仓库完整复制到本地，包含全部历史与分支。
fetch 取回 下载远程新对象并刷新 origin/main，但不动工作区和本地 main。
pull 拉取 fetch + 整合（默认 merge，可配 rebase）；可能产生冲突。
push 推送 把本地提交上传到远程；远程有新提交时默认会被拒绝。
upstream 上游分支 当前本地分支默认跟踪的远程分支；-u 用于首次设置。 git branch -vv 可查看
ahead / behind 领先 / 落后 本地比远程多的提交数 / 远程比本地多的提交数；两边都有就是分叉。 git status -sb
fast-forward 快进 没有分叉时，直接把分支指针前移到目标提交，不生成 merge commit。
non-fast-forward 非快进 新位置不是远程当前位置的后代；推送默认被拒，先整合再推。 见 0003
force push 强制推送 跳过祖先检查，用本地历史覆盖远程；可能抹掉别人的提交，危险。
force-with-lease 带租约强推 仅当远端仍停在你上次 fetch 看到的位置时才覆盖；比 --force 多一道保险。

4. 分支整合

英文中文一句话解释
merge 合并 把两条历史汇到一起；能快进则快进，否则生成 merge commit。 见 0004
merge commit 合并提交 有两个或更多父提交的特殊提交，记录「两条线在这里汇合」。
merge conflict 合并冲突 两边改了同一处，Git 无法自动决定；手工编辑后 git add 再继续。
rebase 变基 把当前分支独有的提交重放到目标分支之后；历史变直线，哈希全变。
replay 重放 rebase 为每个旧提交重新生成一个内容相似、父提交不同的新提交。
common ancestor 共同祖先 两条分叉历史最近的一个共同提交；merge 与 rebase 都以它为参照。
--ff-only 仅允许快进 不能快进就报错，适合确认「本地只是落后、没有分叉」的场景。
--no-ff 禁用快进 即使能快进也强制生成 merge commit，保留「这里曾合并过一个分支」。
Pull Request 拉取请求 GitHub 上的合并提案与评审流程；合并动作由平台完成。
protected branch 保护分支 禁止强推或直接推送的分支，通常要求通过 PR 与检查后合并。

5. 急救与危险操作

英文中文一句话解释
rejected 被拒绝 远程拒绝了这次推送，最常见原因是 non-fast-forward。 见 推送急救卡
stale info 信息过期 --force-with-lease 发现远端在你 fetch 后又变了，于是拒绝覆盖。
reset --hard 硬重置 把分支、暂存区、工作区一起重置到某个提交；会丢未提交改动，危险。
backup branch 备份分支 动手前用 git branch backup-日期 固定当前位置，出问题可回来。
lost commit 丢失的提交 没有分支/标签指向、但可能仍在对象库与 reflog 里的提交；可用 reflog 找回。
conflict markers 冲突标记 文件里的 <<<<<<<、=======、>>>>>>>；解决后必须全部删掉。
