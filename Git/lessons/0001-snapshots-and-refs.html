第一课：快照、提交链与分支指针

这一课只拿一个东西：能在纸上画出「提交链 + 分支指针 + HEAD」，并解释为什么切分支是瞬间完成的。这是后面三节课的地基——远程、push 被拒、merge/rebase，全都建立在这张图上。

1. Git 存的是快照，不是差异

很多人以为 Git 每次 commit 只记录「这次改了哪几行」。不是。每次 commit 记录的是当时整个项目的一份快照：所有文件的目录结构，以及每个文件内容在那个时刻的引用。某个文件没变，Git 就直接复用上一份快照里的同一块内容，不会重复存——所以快照并不等于把整个项目复制一遍。

这个设计带来一个直接后果：切到某个 commit，就是把工作区恢复成那张完整快照；比较两个 commit，就是比较两张快照。Git 不需要从第一天开始把差异一层层叠加起来。Pro Git 把这种思路概括为「把数据看作是对小型文件系统的一组快照」。

一句话记忆：commit 是存档点，不是补丁包。补丁可以丢，存档点不能丢。

2. 提交链：每个 commit 记得它的父亲

一个 commit 对象里至少有这些信息：

字段作用
tree（树）这次快照的目录结构，指向所有文件内容
parent（父提交）上一个 commit 的哈希；根提交没有父提交
author / committer作者与提交者，含时间戳
message（提交信息）你写的说明

父提交把一个个快照串成一条链。哈希（hash）由这些内容一起算出来，所以内容一变，哈希就变。你在 git log --oneline 里看到的 a1b2c3d 是短哈希，完整哈希有 40 个十六进制字符。

合并提交（merge commit）会有两个父提交——它是两条链的交汇点。这一点第四课会展开，现在只要知道「父提交可以不止一个」。

3. 分支：一张写着 commit 哈希的便利贴

分支的本质简单到有点反直觉：它只是一个指向某个 commit 的可移动指针。在磁盘上，.git/refs/heads/main 这个文件里就一行哈希。创建分支不会复制任何文件，只是多写一张便利贴。

# 查看本地分支，-v 顺便显示每个分支指向的 commit
git branch -v

# 创建并切换到新分支：在当前位置贴一张 feature 便利贴，再让 HEAD 指过去
git switch -c feature

# 旧写法（仍然可用）：git checkout -b feature

main 没有任何特殊地位，它只是 git init 默认起的名字。你完全可以叫 trunk、dev 或 zhu。真正特殊的是 HEAD。

4. HEAD：你现在站在哪

HEAD 是「当前所在位置」的指针。正常状态下它指向一个分支，比如 HEAD → main；git switch 做的事就是移动 HEAD，并把工作区更新成目标分支那张快照。

HEAD 也可以直接指向某个 commit，这叫 detached HEAD（分离头指针）。这时你不在任何分支上，新提交没有分支保着，切走之后容易「丢」。初学阶段记住一条：看到 detached HEAD，先新建一个分支再干活。

# 看 HEAD 现在指向谁
git branch --show-current     # 输出当前分支名；detached 时为空
git log -1 --oneline --decorate

# 万一进了 detached HEAD，用一条新分支把当前位置保下来
git switch -c rescue-here

6. 沙箱练习：让文件随分支「消失」又「回来」

先确认沙箱存在。在 Git/ 目录下运行 bash git_sandbox.sh 可搭建；如果提示目录不完整，脚本会建议 --reset——它会删除 sandbox 里的全部内容，只在确认没有要保留的练习时才用。下面的命令都在 Git/sandbox/work 里执行。 
cd Git/sandbox/work

# 1. 看当前历史与指针
git log --oneline --graph --decorate --all

# 2. 建一个分支并切过去
git switch -c feature

# 3. 在 feature 上提交一行笔记
echo "feature 分支上的第三行" >> notes.md
git add notes.md
git commit -m "docs: 在 feature 上记一笔"

# 4. 看两条分支现在各自指向哪
git branch -v
git log --oneline --graph --decorate --all

# 5. 切回 main，观察工作区
git switch main
cat notes.md
#   刚才那行「feature 分支上的第三行」不见了——你回到了 main 的快照

# 6. 再切回 feature，它又回来了
git switch feature
cat notes.md

要观察的三件事：

  1. git branch -v 里 main 与 feature 指向不同的短哈希；
  2. git log --graph --all 里两条件指向同一个分叉点；
  3. 切换分支时，notes.md 的内容跟着变——这就是「快照」最直观的证据。
注意：如果切换时提示有未提交的修改会阻止切换，先 git status 看清是什么，再决定提交、暂存还是丢弃。不要在没看内容前就 git checkout -- .。
