第二课：三区与远程地图——push 之前你站在哪

这一课只拿一个东西：看一条 git status -sb 的输出，就能说出改动当前在「工作区 / 暂存区 / 本地仓库 / 远程」的哪一层，以及 origin/main 为什么不是 GitHub 上的那个 main。

1. 三个本地区域，一条单行道

Git 把「你的文件」分成三层。理解这三层，git status 的每一行才有意义：

区域英文里面是什么怎么把内容放进去
工作区working tree你正在编辑、能直接用编辑器打开的文件正常保存文件
暂存区index / staging area下一次 commit 要包含的内容清单git add <文件>
本地仓库local repository（.git/）完整的提交历史与所有快照git commit

关键点：git add 不是「把文件加入 Git」，而是「把当前内容登记进暂存区」。你 add 之后再改文件，工作区里的新改动不会自动进入暂存区——下一次 commit 仍然只包含你 add 时的那一版。这个「选好再存档」的设计，让你能精确控制每个 commit 的内容。

# 改了一个文件后，status 的三种典型形态
git status -sb
#  M notes.md        ← 工作区有改动，还没登记
git add notes.md
# M  notes.md        ← 已登记进暂存区（第一列是暂存区，第二列是工作区）
git commit -m "docs: 记一笔"
# ## main...origin/main [ahead 1]   ← 已进入本地仓库，但远程还落后一个提交
两列状态字母：git status -sb 的短格式里，左边一列是暂存区，右边一列是工作区。M  notes.md 表示「暂存区里的版本改了，工作区与暂存区一致」； M notes.md 表示「工作区改了，还没 add」。

2. 远程仓库与 origin/main：地图不是领土

远程仓库（remote）是另一个完整的 Git 仓库，通常放在 GitHub 上。它不是「中央服务器」，也不比你的本地仓库高一级——它是大家约定同步的那一份。你 clone 下来之后，本地就有完整历史，离线也能 commit、log、切分支。

origin 只是远程仓库的默认昵称，不是 GitHub 的专属名字。你可以叫它 upstream、company，甚至 backup。用 git remote -v 能看到昵称对应的真实 URL。

真正容易混淆的是 origin/main。它不是 GitHub 上的 main 分支本体，而是你本地的一份缓存：上一次和远程通信时，main 分支在远程的位置。它是 remote-tracking branch（远程跟踪分支），是只读的「地图标记」——你本地不会直接在上面提交。

最重要的一句话：别人向 GitHub 推了新提交，你的 origin/main 不会自动更新。只有 git fetch（或 git pull、成功的 git push）才会刷新这张地图。地图没刷新，不等于领土没变。

4. push、fetch、pull：三条边各自做什么

命令方向动什么不动什么
git fetch远程 → 本地下载新对象；更新 origin/main 等远程跟踪分支不动你的工作区，也不动本地 main
git pull远程 → 本地先 fetch，再把 origin/main 合并进当前分支（默认 merge，可配 rebase）不会自动帮你解决冲突
git push本地 → 远程上传本地提交；成功后更新远程分支，并刷新本地的 origin/main不会自动先拉取；远程有新提交时会被拒

把这三种操作和第一课的分支图接起来：push 成功时，远程的 main 和你的 main 指向同一个提交；fetch 之后，origin/main 追上远程，但你的 main 可能还停在原地——这时 git status -sb 就会显示你落后了几个提交（behind）。

5. 四条命令，随时定位自己

我想知道命令看什么
当前分支、领先/落后git status -sb## main...origin/main [ahead 1, behind 2]
每个本地分支跟踪谁git branch -vv分支后的 [origin/main] 与提交摘要
远程昵称与 URLgit remote -vorigin https://...（fetch/push 两行）
所有分支的图形历史git log --oneline --graph --decorate --all分叉、合并、各引用位置
ahead / behind 怎么读：ahead 1 = 你本地有 1 个远程没有的提交（该 push）；behind 2 = 远程有 2 个你本地没有的提交（该 fetch/pull）。两边都有数字，就是分叉了——第三课的主题。

6. 沙箱练习：让 status 走完四层

沙箱没搭好时，先在 Git/ 目录运行 bash git_sandbox.sh。--reset 会删除 sandbox 内容，只在确认不需要保留旧练习时使用。 
cd Git/sandbox/work
git switch main                 # 第一课如果停在 feature，先回来

# 1. 看远程昵称和 URL
git remote -v

# 2. 第一次推送，并把 main 的上游设为 origin/main
git push -u origin main
git branch -vv                  # 应看到 main 后面跟着 [origin/main]

# 3. 改文件：工作区
echo "第二课：三区练习" >> notes.md
git status -sb                  #  M notes.md

# 4. 登记进暂存区
git add notes.md
git status -sb                  # M  notes.md

# 5. 存入本地仓库
git commit -m "docs: 第二课三区练习"
git status -sb                  # ## main...origin/main [ahead 1]

# 6. 图形化确认：main 比 origin/main 多一个提交
git log --oneline --graph --decorate --all

# 7. 推到远程，地图与领土重新对齐
git push
git status -sb                  # ## main...origin/main（干净）

要观察的：第 3–7 步里，同一行改动依次经过「工作区 → 暂存区 → 本地仓库 → 远程」，而 git status -sb 的提示从  M 变成 M ，再变成 ahead 1，最后消失。这个顺序就是 Git 的主干道。
