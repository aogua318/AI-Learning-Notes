# Mission: Rust 与嵌入式 / 驱动开发

## Why
用户是网络设备相关的运维工程师（用户方，接触不到公司设备的内核层），出于个人兴趣想学会"从设备固件到系统底层"的完整技术栈，并以 Rust 为主线语言。做出能插上电脑就用的实物——格斗游戏摇杆、USB 网络检测盒——是这台学习发动机的火花塞，也是唯一的验收场。

## Success looks like
- 六个月：一个能插上电脑就打《街霸》的格斗摇杆（Rust 固件、通用 USB HID、有线）+ 一个手机 WoL 开机工具（Rust CLI + 同一 WiFi 下的网页按钮）+ Rustlings 主体刷完
- 十二个月：USB 网络检测盒原型（设备端轻量采集 + PC 端 Rust 分析工具，功能为网段活跃设备 top N 与异常告警）+ 读懂一个 Linux Rust 驱动源码
- 每个阶段沉淀一篇"从零手搓"风格的深度文档，延续本仓库 md5 / bt / mp3 三篇的传统

## Constraints
- 每周 5–10 小时，业余学习
- C 语言基础，Python 应用层经验；所有权 / 借用模型是全新心智模型，需要专门的心理建设
- 硬件从零开始：无开发板，不会焊接（愿意学 through-hole，约一小时技能）；起步预算约 ¥200
- Windows 原生开发环境：rustup + UF2 拖拽烧录，不用 WSL
- 公司设备完全黑盒：学习项目一律用自有硬件，公司设备只作灵感来源与认知场景
- 课程交付形式：HTML 互动课为主线，短课（每节 15–20 分钟，一个知识点 + 一个页面内互动练习）；markdown 手搓长文作为阶段沉淀
- **语言规则：用户英语水平有限。教学材料中，代码关键字与专有名词（trait、cargo、winget 等）之外的英文表述，必须附中文对照——保留英文原文，旁边给中文翻译（如编译器错误信息、规则原文、工具界面文案）**

## Out of scope
- Windows 驱动（WDK / 驱动签名 / windows-drivers-rs）——第一年不碰
- 内核驱动编写（Linux / Windows kernel module）——第一年只读不写，第二年再评估
- STM32 平台、embassy async 框架——留到第二阶段（网络检测盒）再上
- 写手机 App、XInput 兼容、蓝牙 / 无线接收器、hitbox 布局——都是摇杆 v2 的事
- 在公司设备上做任何实验——红线
