## 一、借用是什么：传地址，不传所有权

- **借用 = 把地址 copy 一份给别的函数用**，对方直接访问地址指向的内存区；所有权留在原变量手里，原变量照常可用。
- 引用离开作用域**什么都不 drop**——它不是所有者（参观证到期只是作废，房子轮不到它拆）。
- C 类比：&T 像指针，但编译器保证它始终有效（不悬垂）。

## 二、两种引用：只读可多个，可写只能一个

| | 不可变引用 `&T` | 可变引用 `&mut T` |
|---|---|---|
| 权限 | 只读 | 可写 |
| 同时存在数量 | 任意多个 | 只能一个（排他） |
| 是不是 Copy | 是 | **不是**（第一课预告的兑现） |

- 精度补充：**通过引用改数据只有 &mut 行；所有者本人（mut 绑定）随时能改自己的数据**——排他规则限制的是"借用路径"，不是"所有者"。
- 排他规则的精确表述：不是"不能连续声明"，是**作用域不能重叠**。前一个只读引用用完（最后一次使用）之后，&mut 立刻能登场。
- 为什么排他：数据竞争三条件（两个以上指针同时访问同一数据、至少一个在写、无同步机制）——排他让这类错误在 Rust 里根本写不出来。

## 三、引用的生命周期：活到最后一次使用（NLL）

- **曾误**："被使用过一次就结束了"。
- **正解**：作用域从引入处持续到**最后一次使用**（The Book 原文：a reference's scope "continues through the last time that reference is used"）。
- 推论（循环）：循环体内现借现用，每轮迭代是新作用域，重新声明借用天然没问题；要小心的是借用**横跨整个循环**（`for x in &v` 的迭代器持有借用），那循环体内不能改 v。
- "借了尽快用"的直觉由此得到正式解释：不是风格，是作用域天然只算到最后一次使用。
- **编译器视角的操作化规则（用户自主综合，已探针证实）**：每个借用有存活区间 [创建点, 最后一次使用]；两个区间重叠且至少一个是 &mut 就报错，报错点在后出生的那条借用的创建处。要穿插使用就重新声明（遮蔽或换名均可），旧引用到最后一次使用自动退场。
- **边角实证**：从未被使用的借用，存活区间为空——诞生即死。所以 `let ma = &mut s; let a = &s;` 能编译（只有 unused 警告），两个从未使用的 &mut 甚至能共存。规则不是"不能声明两个 &mut"，是"不能同时活着两个"。
- **实现不是栈（用户推断已修正）**：借用死亡顺序非 LIFO（死在自己的最后一次使用，先出生可以先死）；检查器看的是存活借用的**集合**而非栈顶（b 死 a 活时压 ma 仍报 E0502）。真实机制是 rustc 在 MIR 上算区域（region）做重叠检查。栈直觉只在简单直线代码里够用。

## 四、悬垂引用：编译器替你挡的枪

- 函数内部**不能把局部变量的引用交出去**——局部变量出作用域就 drop，引用会比所有者长命。
- 修复：把值本身交出去（返回 String 本体，move 或 copy），而不是返回引用。
- 报错 `error[E0106]`（missing lifetime specifier，缺少生命周期标注）。

## 五、The Book 4.3 阅读笔记：切片与区间

### iter() 与 enumerate()

- `iter()` 产出元素的**引用**（&T）——借来遍历、不夺所有权；要元素本体是 `into_iter()`（夺走集合所有权）。
- `enumerate()` 给迭代器加索引，产出 `(usize, &T)` 元组。
- The Book 里 `for (i, &item) in bytes.iter().enumerate()` 的 `&item` 是**模式解包**（把 &u8 拆成 u8），别误以为 iter 给的是值。

### 区间为什么半开（左闭右开）

- **曾误**："设计原因是拿来取单词，单词天然有空格"。
- **正解**：那是 first_word 的**用法**，不是设计原因。三条真正理由（第一课就写对过）：
  1. **长度 = 上界 − 下界**（闭区间要 +1；嵌入式里 DMA 长度算错就是内存踩踏）；
  2. **相邻区间无缝拼接**（`[0..2)` 接 `[2..4)`）；
  3. **空区间写得出来**（`x..x`）。
- first_word 的 `&s[0..i]` 恰好不含空格，是半开性质的**顺带好处**；闭区间 `&s[0..=i-1]` 同样取到单词，只是更绕。
- 术语：**左闭右开**（不是左开右闭）。第三课正式展开。

## 六、&str vs &String：为什么不是加个 & 那么简单

- 四个不同的东西：`String`（拥有型：堆缓冲+长度+容量，管 drop）、`str`（不定长切片类型，不能单独存在）、`&str`（胖指针：地址+长度，不拥有不管理）、`&String`（细指针，指向 String 结构体）。
- 关键在**通用性**：&String 只能由 String 变来；&str 可以由 String 切片、字符串字面量（字面量本身就是 &str）、任何 &String（Deref 强制转换）变来。
- The Book：收 &str "makes our API more general and useful without losing any functionality"（API 更通用且不损失功能）。
- C 类比：&str ≈ (char*, len)，&String ≈ String*。
- 编译器兜住你的案例：WoL 重构后 `parse_mac(&mac)` 多留一个 &（&&str），Deref 强制转换自动解引用、能跑——认得出就行。

## 七、WoL 重构实战（课后任务 3）

- 弧线：取消 println 注释 → `error[E0382]: borrow of moved value`（编译器还提示"可把参数改成借用"）→ 改签名 → `error[E0308]: expected &str, found String`（提示 consider borrowing: `&mac`）→ 调用处加 `&` → mac 存活。
- 什么时候才该收 `String`：函数要把数据**留存**（存进结构体、塞进 Vec）时；借用只适合"借来看一眼"。

## 八、两个心得

- **风格迁移**：C 是资源视角（先分配再填），Rust 是数据流视角（所有权随数据流走，借用贴着使用点）。每个函数签名回答三个问题：收不收所有权、能不能改、活多久。
- **并发直觉**：&mut 排他 = 编译期版互斥保证，数据竞争被静态消灭（无畏并发的地基）。边界：**同步**（等待/通信/顺序）仍需要 Mutex/通道/原子；Rust 的 `Mutex<T>` 把数据和锁绑成类型，忘加锁在类型层面过不去。

## 九、两处追问的修正（2026-10-20）

1. **move 转移的是值，不是"变量口袋里的所有权令牌"**：所有权是值的属性，变量只是名字。`let s3 = s1` 时 s3 是新生名字，从未拥有过东西；`s2 = s3` 先 drop s2 的旧值（"WORLD"此刻释放）再接收新值。终局 s2 拥有 "HELLO"，s1/s3 是死名字，每值恰好 drop 一次。
2. **"&String 代替 &str 没区别"只在一半情况下成立**：所有调用方都恰好有 String 时没区别；字面量和切片传不进 &String 参数。原则：收能完成任务的最泛类型。

## 十、再追问的修正（2026-10-20）

1. **赋值也会 drop**：`s2 = s3` 先析构旧值再接收新值——drop 的触发不止"离开作用域"，还有"被新值顶替"。
2. **引用生命周期的参数特例**：传给函数的引用，借用持续到函数内最后一次使用（最迟函数返回）；从调用方看"用过一次就结束"是个实用近似，与"活到最后一次使用"不矛盾（传参场景里最后一次使用往往就是那一次调用）。但"随函数结束"只对参数引用成立——同函数内用两次的引用活到第二次。总规则永远是 NLL：到最后一次使用。
