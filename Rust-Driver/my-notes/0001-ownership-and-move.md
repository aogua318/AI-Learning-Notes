## 一、值的两种赋值行为：move 与 Copy

### 1. 总规则（本课最重要的一条）

- **所有值默认 move**：赋值或传参时，所有权转移给新变量，旧变量立即失效。
- **实现 Copy trait 的类型**：赋值时按位复制一份，原变量仍然有效。
- 判据是**类型实不实现 Copy**，与数据在栈上还是堆上无关。这不是运行时的"转换"，是编译期按类型选定的行为。

### 2. 哪些类型是 Copy

| 类别 | 例子 | 说明 |
|---|---|---|
| 内置基本类型 | `i32`、`u32`、`bool`、`f64`、`char` | 定长、纯数据、不拥有资源 |
| 复合类型（递归规则） | `(i32, bool)`、全是 Copy 字段的结构体 | **所有成员都是 Copy，整体才是 Copy**；结构体需显式 `#[derive(Copy)]`（习惯上与 Clone 一起写：`#[derive(Copy, Clone)]`），元组自动 |
| 引用 | `&String`、`&T` | 复制引用不复制所有权；但 `&mut T` **不是** Copy |

关于 `&String` 的分析（当时的拆解，结论正确）：`s` 是 String（move 类型，内部三元组里藏着堆指针），`&s` 是"指向指针的指针"；但**引用值本身是简单的定长数据**，所以 `&String` 实现 Copy，`let r2 = r` 就是复制引用。

### 3. 曾误 → 正解

- **曾误**："栈上的内容可以无视所有权" / "基本类型一般可复制，对象类型有所有权"。
- **正解**：两个反例击穿这个框架——`&String` 是 Copy 但指向堆数据；`struct Player { name: String, score: i32 }` 变量本身在栈上，赋值时却是 move。所有权规则对栈上值一样成立，只是 Copy 类型的赋值行为是复制。

## 二、Drop：时机与机制

### 1. Drop 是什么

- **所有者离开作用域时自动执行的清理动作**。对 `String`/`Vec` 来说就是释放堆内存——C 里手写 `free(s)`，Rust 自动做。
- **不能手动调 `.drop()`**（会和作用域结束时的自动 drop 冲突，构成双重释放）；想提前释放用标准库函数 `std::mem::drop(x)`。
- **Copy 与 Drop 互斥**：Copy 承诺"赋值时复制、两边都有效"，Drop 承诺"出作用域时清理"——同时成立，复制出的每一份都会清理同一资源。
- 出作用域的顺序是**逆序**：后声明的先 drop（同 C++ 析构函数）；panic 时也照常 drop。

### 2. move 之后，堆内存 drop 几次？

**恰好一次。** 时间线：

```rust
let s1 = String::from("hello");
let s2 = s1;
// move 瞬间：对堆数据零操作，只复制栈上三元组 + 编译期标记 s1 失效
// 作用域结束：s2 drop，堆内存释放（唯一一次）；s1 被移空，跳过（零次）
```

- **曾误**："s2 = s1 之后，s1 已经 drop 一次了"——把编译器的"走到 s1 但跳过"理解成了 drop 一次。若真 drop 就是双重释放，那正是 move 要消除的灾难。
- 推论：**drop 的责任随所有权走**。谁拥有，谁负责；所有权转移，责任连同转移。

### 3. 两套内存制度（曾经的混淆点）

| | 堆块（"hello" 缓冲区） | 栈帧（s1、s2 的槽位） |
|---|---|---|
| 谁管理 | 分配器，借了必须还 | 函数调用本身，整帧进出 |
| 怎么回收 | Drop 里的显式归还 | 栈指针一条指令，整体作废 |
| 粒度 | 逐块 | 无逐变量概念，和 C 一致 |

- **曾误**：试图给 s1 的三元组安排一个"释放时机"——这个动作不存在。析构跑完，整个栈帧（含所有局部变量的槽）一次性作废。
- Rust 和 C 在栈上的行为完全一样；唯一差别是析构阶段那一次自动的堆块归还。

### 4. 编译器怎么决定调不调 drop

编译期静态决定，运行期没有"检测"或"扫描栈"：

1. **类型层面**：这个类型的值需要析构吗（有没有实现 Drop，递归查字段）？
2. **变量层面**：这个变量此刻还持有值吗——靠 initialized-places 数据流分析（move paths，精确到字段）算出，三态：未初始化 / 已初始化 / moved。
3. 两条都"是"才生成 drop 调用。

- 判据**不是**"指向堆内存"：GPIO 守卫不碰堆却需要 Drop（释放引脚）；裸指针 `*mut T` 指向堆却没有 Drop（不接回 Box 就泄漏）。
- 唯一需要运行期的例外：**条件移动**（一个分支 move、另一个不 move）时生成 drop flag（布尔量）在作用域结束时检查。
- 部分移动合法：`let s = p.a;` 只移走结构体的一个字段，其余字段照常可用。
- **曾误**："堆内存通过逆序检测当前栈里的变量，查看指向的是否为堆内存区"——这是 CPython 式 GC 的想象；Rust 的 drop 是编译期算好的静态调用序列。

## 三、rustlings 00~06 练习笔记

### 1. 宏与 println!（intro2）

- `println!` 是**宏**（`!` 是调用宏的记号）：编译期解析格式串，把 `{}` 占位符和参数对上，再展开成代码。函数不能变参，宏可以模拟。
- `"hello world"` 这个格式串本身是**一个整体**（一个字符串字面量）；可变的是 `println!` 的参数列表（格式串 + 零到多个值）。
- `println!("Number {x}")` 是 Rust 2021 内联格式参数，自动捕获同名变量；等价原始形式 `println!("Number {}", x)`。
- 现阶段把 `println!` 当完整函数用没问题，但记住宏与函数的分工：宏编译期展开，函数运行期调用。

### 2. 变量（variables3~5）

- 变量**默认不可变**；`mut` 声明可变绑定；已实测 `price = price - 10` 在不可变绑定上编译不过。
- `let x` 同名重绑是**遮蔽**（shadowing）：这是新变量不是改值，**可以顺便更换类型**——和"重新赋值"是两回事。

### 3. 常量（variables6）——未决，待语言机制课

- `const` 必须显式标注类型；值必须是编译期可求值的常量表达式；没有 `const mut`；命名约定全大写下划线。
- 与 `let` 的本质区别：`const` 是编译期常量、无固定地址、被内联进每个使用处；`let` 是运行期绑定。
- 固件用途预告：寄存器地址、缓冲区大小的标准写法（`const LED_PIN: u8 = 25;`）。

### 4. 函数：尾表达式与分号（functions4~5）

- **分号是"表达式→语句"的开关**：加分号，值被丢弃、类型变 `()`；不加，函数体最后一个表达式的值就是返回值——这叫**尾表达式**。显式 `return` 也合法，两路并存。
- `price - 10` 作为函数结尾，含义确实是"返回 price - 10"，但它不是函数调用，是尾表达式语义。
- 与 C 的区别：C 里最后一个表达式不加分号是语法错误；Rust 里恰恰是返回值。这就是"分号作用和 C 不一样"的实质。

### 5. if 表达式的类型（if1）

```rust
if a > b { a }    // 编译错误 E0308：expected `()`, found `i32`
b
```

- **曾误**："if 隐含了 else"。正解：**没有 else 的 if，整个表达式类型必须是 `()`**（条件为假时什么都不产生）；块末尾产出 `i32` 就对不上类型。
- 修复两条路：块内写 `a;` 把值丢掉（当语句用），或补上 `else` 让 if 表达式产出 `i32` 当尾表达式。

### 6. 数组切片与区间（primitive_types4）——未决，第三课展开

- 语法 `&a[1..4]`：左闭右开（取下标 1、2、3）。
- 半开区间的好处：**上界减下界即长度**（`4 - 1 = 3`，闭区间要算 `+1`，嵌入式里 DMA 长度算错就是内存踩踏）；**相邻区间无缝拼接**（`[0..2)` 接 `[2..4)`）；**空区间写得出来**（`x..x`）。
- Rust 也提供闭区间变体 `a[1..=4]` 供需要时用。

### 7. 元组（primitive_types5）

- 访问语法 `cat.0`、`cat.1`；索引越界（访问不存在的下标）**编译期**就报错。

### 8. 迭代器链（vecs2）——未决，后续专课

```rust
input.iter().map(|element| element + 1).collect::<Vec<i32>>()
```

- `|element| element + 1` 是**闭包**（匿名函数）：拿来一个元素，返回加一后的值。
- 三层结构：`.iter()` 借来遍历（不夺所有权）→ `.map(闭包)` **惰性**逐个变换 → `.collect()` 才真正执行并收成新容器。迭代器是惰性的，不 collect 什么都不发生。

### 9. move_semantics 四、五（借用的第一印象）

- `&mut T` 同一时间只能有一个——**排他**。完整规则（为何排他、和只读借用的关系）见第二课。
- **传 `&T` 不取所有权（借），传本体取所有权（move）**。
- 术语纪律：`&T` 叫**引用**，不叫"指针"——"指针"在 Rust 专指 `*const`/`*mut` 裸指针（无检查、unsafe）。
