# 学习者档案（Learner Profile）

> 本文件回答一个问题：**这是一个什么样的学习者，该怎么教**。与 MISSION.md（目标）、NOTES.md（进度）、learning-records/（心智模型演变）并列，新会话必读。
> 所有结论基于会话中的实际行为证据，非印象评价。由 AI 维护，每完成一课或偏好发生变化时更新。最后更新：2026-10-22（第五课完成与批阅落盘）。

## 一、背景与约束

- **基础**：C 语言（熟悉内存与指针），Python 应用层经验（本仓库 ADB/MCP/Git 项目为证）。
- **身份**：网络设备相关运维工程师，用户方；公司设备完全黑盒（无测试机、无 root），学习成果的检验场只能是自有硬件。
- **时间**：每周 5–10 小时，业余学习。
- **硬性语言约束**：自评英语水平有限。教学材料中，代码关键字与专有名词之外的英文（规则原文、编译错误信息、工具界面文案）必须保留英文并附中文对照。已写入 MISSION.md Constraints，强制执行。

## 二、学习能力评估（基于证据）

### 强项

1. **自学闭环完整且稳定**：做题 → 写编号笔记 → 中途自我修正 → 带着具体问题回来。作业笔记中多次当场自我纠错（"一开始的不需要重新赋值是错的"、对 if 机制的追问修正）。
2. **主动交叉验证**：用 variables5 验证 variables4 的结论；实测 `price = price - 10` 报错验证不可变规则；指出"functions5 刚好说明分号的作用"。习惯用第二个实验确认第一个结论。
3. **主动建立知识连接**：用 Python 引用计数类比 Drop（类比本身是错的，但行为说明他在主动往旧知识上挂新知识——教学时应先肯定连接意图，再纠正映射）。
4. **抽象层级爬升快，且能自主综合规则**：几轮之内从"栈/堆"的具体框架爬到"编译期数据流分析"的机制层；第二课追问弧线中自主综合出 NLL 的完整操作化规则（探针证实），独立重发现"排他 = 编译期互斥"的并发洞察（并自行补上数据竞争与同步的边界）。
5. **进度持续超前且会自选加练**：语言预备期原计划 4 周，实际已通关第一至四课全部作业，第五课 CP1–CP3（const/static 三轴、WoL const 块与定长魔术包）也已完成；strings3 还自行用了迭代器写法。

### 固有模式（教学时要预判，不是缺陷）

1. **"栈/堆"框架三次复现**（LR-0001/0002 有完整记录）。每次复现内核都在改善。纠偏方式：用同一组反例（`&String` 是 Copy 但是指针；含 String 字段的结构体在栈上却是 move）点破即可，**不要长篇大论**——反例对他有效，说教无效。
2. **倾向用"运行时机制"解释编译期事物**：曾把 drop 想象成"逆序扫描栈找指向堆的变量"（CPython GC 的模型）；第二课又推断出"栈模型"的死亡机制，被反例击穿（真实机制是 MIR 区域数据流）。讲任何编译期概念时，开场就声明"这是编译期还是运行期"。
3. **用例锚定偏差**（第二课新发现）：区间半开的三条设计理由他在第一课就写对过，但第二课的 first_word 用例出现后，用例"覆盖"了抽象原理，把用例当成了设计原因。教学含义：**引入具体用例时，必须显式重锚原理**（"这个用例利用了原理，但用例本身不是原理存在的原因"）。
4. **英语依赖**：看到未翻译的英文报错会卡住。给英文错误信息时，主动附中英对照表。
5. **笔记是临时提问式，自评"没有逻辑性系统性"**：需要 AI 按主题整理落盘（my-notes/ 规则已立）。每课结束主动提议整理，不用等他要求。
6. **可变借用与所有权转移混淆**（2026-10-21 第三课作业新发现）：把 `s.clear()` 说成"所有权已经给出去了"。这是第一课 move 模型与第二课借用模型的边界没焊死。纠偏方式：亮方法签名 `&mut self` + 错误编号对照（E0502 借用重叠 vs E0382 移动后再用），一句话"借用 ≠ 移动"。
7. **手写循环的边界盲区**（2026-10-21 strings3）：`trim_me` 四个测试全过，但空串与全空白都越界 panic；倾向于把"测试通过"当成正确性证据。教学含义：手搓循环必须补空输入、全空白、无匹配三类边界，用探针实测而不是口头提醒。
8. **自学超前使用未学 API**（2026-10-21 strings3）：用了 `iter().enumerate().rev()`——课程尚未讲迭代器。不是错误，反而说明他读了 Book 原版；处理方式是肯定 + 记账，正式概念留到专课，批阅时区分"任务超纲"与"学生自选超前"。
9. **抽象概念需要最小例子 + C 映射 + 类型链**（2026-10-21 第四课）：直接从 The Book 定义讲闭包，用户明确说"不知道闭包是什么意思"；换成 `add_n` 最小例子和 C 的"函数指针 + 上下文结构体"后立刻收敛。`iter()` 的返回值也靠 `it / it.next() / &i32` 三行类型链才钉准。教学含义：新抽象先给可运行的最小例子，再给定义；类型链比长解释有效。
10. **惰性执行与类型归属易混**（2026-10-21 第四课）：把 `map` 想成"构造时内部跑循环并生成容器"，把 `collect` 的目标类型归给接收者。纠偏：带打印的闭包证明 map 构造时不执行、collect 才驱动；`let out = ...collect()` 的 E0283 证明类型由上下文决定。教学含义：讲惰性/适配器用"什么时候打印"的时序证据；讲 collect 用类型标注反例。
11. **"编译期"一词会吞掉存储/地址/可变性三轴**（2026-10-22 第五课 CP1）：连续两轮把 `const`/`static` 都描述成"编译期分配、只有一份"，并认为 `static` 可直接改；第三轮才用三轴表分开（const 不保证份数/地址；static 固定一份；普通 static 不可变、static mut 才可改且 unsafe）。教学含义：讲 const/static 必须把**求值时机、存储与地址、可变性**分三列讲，不能只贴"编译期/运行期"标签；反例用 `&CONST` 与 `&STATIC` 的地址保证差异。

## 四、教学策略结论（给未来 AI 的可执行清单）

1. **保持"短课 → 练习 → 笔记批阅"循环不动**——这是他自学闭环的轴承，改动它风险最高。
2. **每个新概念先给 C 锚点，再给 Rust 规则**——C 背景是他最大的杠杆，对比式讲解命中率最高。
3. **讲编译期机制前先声明归属**（"这是编译期决定的"），预防运行时想象。
4. **纠偏用反例，不用说教**：一组精准反例胜过三段解释（栈堆框架三次纠偏全部靠反例收敛）。
5. **布置作业前审计概念清单**：练习里不得出现未学概念（出题纪律）；含生概念的题目降门槛或推迟。
6. **用例与原理分离**：给具体用例时显式重锚抽象原理，防用例锚定偏差（区间误区的教训）。
7. **节奏可加速**：他的吞吐能力已被反复验证，一课并一课或加大作业量均可评估。
8. **英文报错一律附中英对照表**。
9. **每课结束主动提议整理学生笔记落盘**——他会持续产出高质量临时笔记，别让它沉在聊天记录里。
10. **固件阶段注意**：no_std 无分配器、栈帧编译期定死——他已在笔记里建立"两套内存制度"的地图，讲到调栈溢出、Drop 守卫时直接引用。
11. **讲方法先看 `self` 签名**：`&self`（只读借用）、`&mut self`（可变借用）、`self`（所有权转移）——这是防止"clear = move"一类混淆的通用抓手。
12. **手写循环先补边界测试**：空输入、全空白、无匹配、全匹配；测试通过不等于正确，探针实测优先。
13. **超前 API 不打断、要记账**：学生自选的未学概念先肯定，再在专课里形式化；不让它挤占当前课的工作记忆。
14. **抽象先给最小例子与类型链**：闭包/迭代器这类新抽象，先用 5 行可运行例子 + C 映射，再给定义；关键表达式写成 `表达式 → 类型 → 指向` 的类型链。
15. **惰性用副作用演示**：用 `println!` 放在 map 闭包里，让用户看到“map 构造完还没执行、collect 才开始”；collect 的目标类型用 E0283 反例讲。
