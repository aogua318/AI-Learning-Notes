# 第四课聚类：闭包与迭代器——从“不知道闭包”到类型链与惰性模型（2026-10-21）

本记录覆盖第四课《闭包与迭代器》的完整学习弧线：CP1（概念笔记）、CP2（first_word 迭代器版 + 四边界输出）、CP3（parse_mac 流水线 + print_hex enumerate）的批阅与纠偏。对应课程：lessons/0004-closures-and-iterators.html。

## 一、CP1：三次迭代才收敛的类型链

**起点**：用户直接说“我不知道闭包是什么意思”。课程原稿从 The Book 定义和 C 类比切入，跳过了最小可运行例子，导致抽象定义没有落点。补上 `let add_n = |x| x + n; add_n(5)` 的最小例子后，用户才把“闭包 = 函数 + 记住外部变量”挂上 C 的“函数指针 + 上下文结构体”。

**第一次复述的问题**：
- 把 `iter()` 的类型说成 `&i32`，并认为 `&i32` 指向游标；
- 认为 `&iter().next()` 才是指向数据的地址；
- 把 `map` 想成“内部有循环，循环完生成容器，collect 再转换”；
- 把 `collect` 的目标类型归因于“接收者”。

**纠偏过程**：
1. 用类型链拆开三样东西：`iter()` → 迭代器对象（游标）；`next()` → `Option<&i32>`；`&i32` → v 中的元素。游标内部指针不暴露；`&iter().next()` 是临时 Option 的地址，不是数据地址。
2. 用带打印的闭包演示 map 的惰性：先打印“map 构造完了”，collect 之后才逐条打印“map 正在处理”。据此建立“消费者驱动、Map 每次只拉一个”的 pull 模型，取代“map 内部循环”。
3. 用 `let out = ...collect();` 实测 E0283，说明目标类型由上下文（变量标注/返回类型）决定，不是接收者；collect 一边 next 一边构造集合，不是先跑完再打包。
4. 用户最终复述：“it 是迭代器；next 返回元素引用；&i32 指向元素，不是指向迭代器。”语义已对，只差把第二空写成 `Option<&i32>`——CP1 通过。

**保留的关键精度**：`next()` 返回的是 `Option<&i32>`（引用 + 可能结束），不是元素本体；元素仍在 v 里，不复制、不移动。

## 二、CP2：first_word 迭代器版——代码对，性能解释错

**代码**：WoL 中 `first_word` 改为 `for (i, &item) in bytes.iter().enumerate()`，`&item` 解包 `&u8`，与 `b' '` 比较；四边界输出正确（`"Hello"` / `"Solo"` / `""` / `""`）。缺空格 `(i,&item)` 只是 rustfmt 风格问题。

**对比句的误区**：用户写“索引版需要用时再用，减少了把时间花在全量预加载上”。判定：不成立。两种版本都按需读取、都不预加载；索引循环同样取一个算一个。真实差别是：索引版手动维护 `i`、`bytes.len()`、边界；迭代器版让 enumerate 管下标、`&item` 管解包，少一份手写状态。性能上迭代器是零成本抽象，通常编译成相近机器码，不存在“减少预加载”的优势。

**CP2 结论**：代码与输出通过；对比句按“状态管理/写法差异，不是性能差异”纠正后通过。

## 三、CP3：parse_mac 流水线与 print_hex

**代码**：`parse_mac` 从手动 push 改为：

```rust
mac.split('-')
    .map(|part| u8::from_str_radix(part, 16).unwrap_or(0))
    .collect()
```

类型链 `&str`（split）→ `u8`（map 闭包）→ `Vec<u8>`（collect）正确；`print_hex` 也改为 `packet.iter().enumerate()`，`&item` 解包后直接 `{:02X}`。`cargo run` 输出与重构前一致，102 字节魔术包不变；四个 first_word 边界仍正确。CP3 通过。

**小改进建议**：`println!("3：{}", first_word(""))` 的空串不可见，改为 `{:?}` 会显示 `""`；旧实现注释可按仓库规范删除，或保留到复习结束。

## 四、本轮学习者信号（给后续课程）

1. **抽象概念必须先有最小可运行例子 + C 映射**：Book 定义先行对本次无效；“add_n + 函数指针/上下文结构体”立刻见效。这与既有“C 锚点”策略一致，但本次证明：抽象定义不能打头，例子必须打头。
2. **类型归属需要显式类型链**：用户能把“游标/元素引用/数据”混成一个 `&i32`。写出 `it` / `it.next()` / `&i32` 三行类型链后迅速收敛。后续 trait/泛型/生命周期课应沿用“类型链表”。
3. **惰性执行需要演示，而不是定义**：用户把 map 想成构造时跑循环；带打印闭包的 pull 演示一次纠正。后续讲迭代器组合、async/await 的惰性时，继续用“什么时候打印”的时序证据。
4. **对比句容易滑向性能民间理论**：用户编出“索引版减少全量预加载”。纠偏抓手是“两种都是按需读取”+“零成本抽象/相近机器码”，不要只说“迭代器更优雅”。
5. **收集证据的表达可更清楚**：空串输出用 `{}` 看不见；建议 `{:?}` 或明确标签。未来作业验收可提前给输出模板。
