# 第一课聚类：move / Copy / Drop 心智模型的建立与纠偏（2026-10-19）

本记录覆盖第一课《所有权与 move 语义》的完整学习弧线：从初始框架到四次纠偏，再到 rustlings 通关验收。按时间顺序组织，演进痕迹即价值。对应课程：lessons/0001-ownership-and-move.html。

## 一、初始框架与第一次纠偏：栈堆 → Copy trait

用户自学笔记用"栈上内容可无视所有权（出栈全回收）""基本类型可复制、对象类型有所有权"的框架理解 move 与 Copy。方向对，判据错。已纠正：真正的判据是**类型是否实现 Copy trait**（定长、不拥有堆资源、未实现 Drop），与数据在栈上还是堆上无关。证据：`&String` 是 Copy 但指向堆数据；`struct Player { name: String, score: i32 }` 变量本身在栈上，赋值时却是 move。当时预测：此框架偏差会在借用和 derive 两处复发。

## 二、框架复发，但内核已换

第二轮笔记中框架果然复发（"栈上的内容属于 Copy 类型"），但性质已变：用户自带"默认按位拷贝、独立内存区、不是指针"的正确直觉——外壳还在，内核已被正确判据替换。同轮新进展：复合类型 Copy 递归规则被独立复述且措辞准确（"也可以是 Copy"）；主动追问 move 之后 s1 的 drop 时机，说明正在把 move 与 drop 接起来。残余漏洞：`&String` 正是指针却是 Copy，"不是指针"不能当判据。

## 三、drop 两个误区：move 即 drop、Drop 即引用计数

第三轮出现两个新误区，均当场纠正：

**误区一："s2 = s1 之后，s1 已经 drop 一次 了"。** 实际：move 的瞬间对堆数据没有任何运行时操作（只复制栈上三元组 + 编译期标记 s1 失效）；堆内存的 drop 全程恰好一次，发生在新主人 s2 离开作用域时。作用域结束时编译器"走到" s1 但跳过——那是 drop 零次，不是一次。

**误区二："Drop 类似 Python 的引用计数，没被引用就立即释放"。** 实际：默认借用（&T）是编译期检查，零运行时成本，没有计数；drop 的触发条件是**所有者离开作用域**（确定性时机），与还有没有引用无关。借用检查器静态保证引用一定先于所有者死亡。Python 式 refcount 在 Rust 里的对应物是 Rc/Arc（共享所有权，第二阶段工具）。

预测复发点：mem::drop 提前释放与 drop flags 处（误区一）；"为什么不能返回局部变量的引用"和 Rc/Arc 处（误区二）。

## 四、栈帧整体弹出 vs 堆分配器逐块释放

用户在 move/drop 时序追问中显示所有权转移 + "恰好一次 drop" 已正确建立，但把栈上变量槽的回收也想象成了逐变量的"释放动作"。已纠正：两套制度——堆块由分配器管理、需要显式归还（String::drop 干的唯一事）；栈帧整体进出（一条栈指针指令），析构函数只为还拥有值的变量生成，栈槽随帧弹出一次性作废，没有任何代码参与。C 里函数返回时局部变量同样瞬间消失；Rust 与 C 在栈上行为一致，唯一差别是自动 drop 调用。此区分在固件阶段会再次具体化（no_std 无分配器、栈帧大小编译期定死）。

## 五、drop 的编译期本质（残余误差纠正）

用户一句话总结 drop 机制时把静态析构想象成运行时扫描（"逆序检测当前栈里的变量，查看指向的是否为堆内存区"）。已纠正（rustc-dev-guide moves-and-initialization 页已核实）：rustc 在编译期为每个局部变量维护 initialized-places 数据流（move paths，精确到字段），三态为 未初始化 / 已初始化 / moved；作用域出口只给"类型实现 Drop 且仍持有值"的变量生成调用。判据不是"指向堆"：GPIO 守卫不碰堆却需要 Drop，裸指针 `*mut T` 指向堆却没有 Drop。唯一运行期例外：条件移动时生成 drop flag（布尔量）。部分移动（移动结构体的单个字段）合法，是 move paths 精细度的体现。

## 六、验收里程碑：rustlings 06_move_semantics 通关

2026-10-19 用户完成 move_semantics 六个练习（第一课作业）。练习中正确运用 move / Copy / &T / &mut T。批阅十一条做题笔记：尾表达式语义、遮蔽、mut 不可变规则均独立复述正确；两处判断修正——① 误以为 println! 的参数是"序列化"的（实际格式串是整体，可变的是参数列表）；② if 无 else 时误以为"隐含 else"（实际是无 else 的 if 类型必须为 ()，块产出 i32 才报 E0308）。三个开放问题留待后续课程：const 常量特殊性、区间半开 [1..4) 的设计理由、闭包与迭代器链。

**里程碑动作**：move / Copy / Drop / 引用 / 可变绑定 / 遮蔽 / 尾表达式等 9 词条晋升术语表；第二课《借用与引用》（lessons/0002-borrowing-and-references.html）开启，其主题（&mut 排他）正是用户笔记"可变借用只能有一次，设计思想是借了尽快用？"的直觉问题——课中已修正为编译期强制的排他访问规则。
