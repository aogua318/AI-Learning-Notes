## 一、切片本质：正确，补一个精度

用户笔记原话：“字符串切片只是借用，不是生成一个新的对象，本质还是在访问同一块内存区。”

判定：正确，且抓住了“不复制数据”这个核心。精度补充：`&str` 本身是一个新的引用值——胖指针（地址 + 长度，两个字宽）；不新的是底层字符串数据。这个区分对 drop 有意义：切片没有析构责任，只有引用生命周期。C 类比 `(char*, len)` 在此完全成立。

## 二、半开区间：第二课的用例锚定误区正式收口（作业 1）

用户给出的三条设计理由：直接计算长度、相邻区间无缝拼接、`x..x` 合法——三条全对，且**没有再提 first_word**。这是本轮最有价值的验收：第二课中“把 first_word 的用法当成设计原因”的误区已经拆掉，原理与用例重新分离。

一处小精度：`x..x` 是合法区间，但对 `String` 切片仍要求 x 是 UTF-8 字符边界且在 `len` 内；越界是运行期 panic，不是编译期错误。

## 三、first_word 第一版：下标 vs 长度的精度问题（作业 1）

用户原话：“第一版 first_word 返回的是第一个单词的长度。”

实际：返回第一个空格的下标；无空格时返回 `s.len()`。first_word 的单词恰好总是从下标 0 开始，所以数值上它确实等于第一个单词的长度；但返回值的语义是“空格的位置”，换一个从中间开始的词，下标和长度就分家。更关键的差别在类型：`usize` 不携带“它属于 s”的来源信息，s 之后怎么变它都不受影响；第二版返回 `&str`，切片把 word 与 s 绑定，才让借用检查器能出手。这不是深层误区，但必须拧正：理解两版差异的关键是“返回值的类型是否携带与 s 的关联”，不是“返回数字还是字符串”。

课程 HTML 已加“精度补丁”段落，明确 5 是空格下标而非长度。

## 四、WoL 实现与 E0502：可变借用被误当成所有权转移（作业 2，核心纠偏）

**实现**：`fn first_word(s: &str) -> &str`，索引循环版，无空格返回 `&s[..]`，完全正确；签名比 Book 的 `&String` 更泛。`cargo run` 验证 `"Hello World"` → `"Hello"`、`"Solo"` → `"Solo"`。

**两层报错**：

1. **E0596**：`s` 未声明 `mut`，`clear()` 需要 `&mut s`。用户解释正确。
2. **E0502**：用户解释为“s.clear() 之后所有权已经给出去了，所以 s 借出的 word 也失效了”。

判定：**错误，且是第一课 move 模型与第二课借用模型的混淆复发**。`String::clear` 的签名是 `&mut self`——它可变借用，不取得所有权。`word` 是仍然存活的不可变借用（clear 之后还要被 `println!` 使用），两个借用区间重叠，所以编译器禁止 clear。因果方向恰好相反：不是 clear 让 word 失效，而是 word 还有效，所以 clear 不许发生。若所有权真的被移走，报错会是 E0382（borrow of moved value），而不是 E0502。

**NLL 边界实证**：把 `println!("{word}")` 放在 `s.clear()` 之前即可编译——word 的最后一次使用结束，不可变借用退场，clear 的 &mut 才能登场。规则不是“clear 不能跟在借用后”，而是“借用区间不能重叠”。

用户随后复核确认：“是可变借用与不可变借用重叠的问题”——概念收敛，E0502 已从“所有权转移”改挂到“借用区间重叠”。

**收尾**：WoL 的 main 已改为可编译的 NLL 演示，E0502 反例以注释保留在文件末尾；`cargo run` 通过。课程第 5 节同步补了“clear ≠ move”的常见误读提示。

## 对后续课程的含义

- **迭代器课从用户的 strings3 代码切入**：先讲 `iter()` 产出 `&T`、`enumerate()` 产出 `(usize, &T)`、`rev()` 要求双端迭代器；再回看 Book 版 first_word，最后把索引循环版与迭代器版做对照。用户已有“能跑通”的经验，正好把直觉形式化。
- **讲任何方法前先看 `self` 签名**：`&self` / `&mut self` / `self` 分别对应只读借用、可变借用、所有权转移；这是防止“clear = move”类混淆的通用抓手。
- **错误编号对照表**：E0502（借用重叠）vs E0382（移动后再用）vs E0596（绑定不可变）——用编号而不是长篇解释来纠偏，符合该学习者“反例有效、说教无效”的特点。
- **手写循环的边界测试**：空输入、全空白、无匹配、全匹配；先写测试再写循环，防止“测试过 = 正确”的错觉。
- **审作业时区分超前与超纲**：学生自选的超前 API 应肯定并记账，不作为任务失败；但正式讲解仍按课程顺序，避免工作记忆被生概念挤占。
