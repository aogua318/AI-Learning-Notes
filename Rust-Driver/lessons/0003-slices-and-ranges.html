1. 切片是什么：引用 + 一段范围

第二课说"数据不用送出去，可以借出去"。但借整个 String 有时候太粗了——你只想看其中五个字符，怎么办？答案是切片：引用集合中一段连续的元素。《The Rust Programming Language》第 4.3 节的定义（原文已核实）：

Slices let you reference a contiguous sequence of elements in a collection. A slice is a kind of reference, so it does not have ownership.
（切片让你引用集合中一段连续的元素；切片是一种引用，不拥有所有权。）

两种最常见的切片：&str（字符串切片）和 &[T]（数组等集合的切片，如 &[u8]）。注意这句话怎么接上第二课：切片 = 借用 + 范围。它不拥有数据，所以不触发 drop；它活着的时候，原数据连改都不让改——第 5 节会看见这条规则发力。

C 程序员的类比：&str ≈ (char*, len)——一个地址加一个长度，两个字段打包在一起，所以叫胖指针。你 WoL 项目里的 print_hex(packet: &[u8]) 收的就是字节切片：函数拿到"缓冲区地址 + 长度"，能读全部字节，但一块内存都不拥有。

3. 区间语法：左闭右开

let s = String::from("hello world");

let hello = &s[0..5];    // 含下标 0，不含下标 5 → "hello"
let world = &s[6..11];   // 含下标 6，不含下标 11 → "world"

let sl = &s[..2];        // 省略开头 = 从 0 开始
let sl = &s[3..];        // 省略结尾 = 一直到末尾
let sl = &s[..];         // 全省略 = 整个字符串

let n = &s[0..=4];       // 闭区间变体：含两端，0..=4 → "hello"

术语先拧正：a..b 是左闭右开——含左端点、不含右端点（你笔记里写成过"左开右闭"，课程任务文案里也有同样的笔误，已一并修正）。a..=b 是闭区间，含两端，rustlings 里你见过。

一条实现注意：字符串切片的下标必须落在 UTF-8 字符边界上——切到多字节字符中间，程序运行到那行会直接退出（panic）。纯英文 ASCII 场景碰不到，以后处理中文时要留心。

4. 半开区间的三条设计理由（本课核心）

曾误（你 4.3 阅读笔记的原话）："左开右闭的设计原因是拿来取单词，因为单词天然有空格。"
正解：那是 first_word 的用法，不是设计原因。三条真正理由你第一课就写对过（见下表）。first_word 里 &s[0..i] 恰好不含空格，是半开性质的顺带好处——闭区间写 &s[0..=i-1] 一样取到单词，只是更绕。
理由说明你的现场
长度 = 上界 − 下界 闭区间还要 +1，多一步就多一个出错机会 DMA 传输长度、缓冲区窗口——算错一位，搬移的数据就错一位，嵌入式里这就是内存踩踏
相邻区间无缝拼接 [0..2) 接 [2..4)，不漏不重 分包解析、流水线分段
空区间写得出来 x..x 合法，长度 = 0 "从某处取零个"是合法操作，不用写特例分支

这三条是语言设计者的账本，和"取单词"没关系。记住这个区分：用例解释的是"怎么用"，设计理由解释的是"为什么这样定"——你第一课的笔记分得很清，4.3 阅读时被 first_word 的例子带偏了，这是很常见的读法陷阱。

5. first_word 两版：切片和借用规则的合力

The Book 4.3 用同一个函数写了两版，这是全书最值得细读的一段。第一版返回下标：

fn first_word(s: &String) -> usize {
    let bytes = s.as_bytes();
    for (i, &item) in bytes.iter().enumerate() {
        if item == b' ' {
            return i;      // 返回空格的下标
        }
    }
    s.len()
}

let mut s = String::from("hello world");
let word = first_word(&s);   // word = 5
s.clear();                     // s 被清空——word 还是 5，但它已经什么都不是了
// 编译器不管：5 是个孤立的数字，和 s 的死活脱钩了

第二版返回切片：

fn first_word(s: &String) -> &str {
    let bytes = s.as_bytes();
    for (i, &item) in bytes.iter().enumerate() {
        if item == b' ' {
            return &s[0..i];   // 返回切片，不是数字
        }
    }
    &s[..]
}

let mut s = String::from("hello world");
let word = first_word(&s);
s.clear();   // 编译错误 error[E0502]：cannot borrow `s` as mutable
             // because it is also borrowed as immutable
             //（s 正被不可变借用着，不能同时借成可变）

为什么第二版能抓住第一版抓不住的 bug？因为切片把"取出来的东西"和"原数据"绑成了生死共同体：word 活着，s 就不许改——这正是第二课排他规则的威力。第一课消灭的是"释放后使用"，这一课顺带消灭的是"数据变了，下标/指针还在"。

（iter()/enumerate() 是迭代器，后面有专课；现在认得"逐个扫描、带下标"即可。）

6. 字符串字面量就是 &str

let s = "Hello, world!";

The Book 原话：The type of s here is &str: It's a slice pointing to that specific point of the binary.（这里 s 的类型就是 &str：一个指向二进制文件中特定位置的切片。）字面量不可写、不可变，原因也在这——&str 是不可变引用。

回扣你第二课的笔记 8：&str 是最通用的字符串参数。你的 WoL 代码里 parse_mac(mac: &str) 以后可以直接吃字面量——parse_mac("AA-BB-CC-DD-EE-FF") 合法，不用先造一个 String。

7. 切片作为参数：收最泛的类型

The Book 的结论（原文已核实）：Defining a function to take a string slice instead of a reference to a String makes our API more general and useful without losing any functionality.（函数收字符串切片而不是收 &String，API 更通用、更好用，且不损失任何功能。）三种写法各能收什么：

参数写法能收什么什么时候用
f(s: &str)String 的切片、字符串字面量、&String（Deref 强制转换自动变 &str）只读文本——默认选择
f(s: &String)只有 &String几乎不用——限制更强，能力没多
f(s: String)只有 String 本体（收走所有权）要把数据留存（存进结构体、塞进 Vec）

原则一句话：收能完成任务的最泛类型。函数只读文本，就收 &str。
