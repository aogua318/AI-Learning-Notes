第六课：模块与可见性——给代码划边界

第五课已结课：const/static 三轴、编译期断言、102 字节定长魔术包都完成了。今天把 WoL 从“一个文件装下所有函数”拆成有边界的房间。
开场先声明归属：模块系统是编译期的命名空间 + 可见性检查；运行期没有模块对象，也没有额外开销。 mod 不是 C 的 #include，不会把文件文本复制一遍；它是在模块树里登记一个模块，编译器只加载一次。

本课示例均用 rustc 1.99.1（edition 2021）实测；英文原文与报错附中文对照。

1. 最小模块：先给函数一个房间

mod wol {
    pub fn packet_len() -> usize {
        102
    }
}

fn main() {
    println!("{}", wol::packet_len());
}

模块树是长这样的：

crate（src/main.rs）
└── wol
    └── packet_len（pub）
  • mod wol { ... } 定义一个内联模块；src/main.rs 是二进制 crate 的根（crate root）。
  • wol::packet_len() 是从 crate 根出发的相对路径；完整写法是 crate::wol::packet_len()。
  • packet_len 前面的 pub 让它对父模块可见；去掉 pub，main 就调不到。

去掉 pub 的编译错误（已实测）：

error[E0603]: function `packet_len` is private
（错误[E0603]：函数 `packet_len` 是私有的）
note: the function `packet_len` is defined here
（注意：函数 `packet_len` 定义在这里）

要分清两个开关：模块本身的可见性和模块里项的可见性。路径上的每一层都要放行，才能从外面走到目标项。

mod outer {
    mod inner {
        pub fn value() -> i32 { 7 }
    }
}

fn main() {
    // 即使 value 是 pub，inner 仍是私有模块
    println!("{}", outer::inner::value()); // E0603: module `inner` is private
}
规则：默认私有。子模块能看见祖先的项（所以后面有 super::）；祖先不能看见子模块的私有项。把路径中间的模块或目标项标成 pub，才会向上一层放行。

1.1 C 锚点：mod 不是 #include

C 写法Rust 对应关键差别
#include "foo.h" 没有直接对应；用 mod foo; 声明模块 C 是文本包含；Rust 是语义上的模块声明，只加载一次
文件作用域的 static 函数 默认私有（当前模块及后代可见） Rust 默认不导出，需要 pub 才放行
头文件里的声明 pub fn / pub use Rust 没有头文件；公开 API 由 pub 和 use 共同塑造

2. 可见性刻度：从私有到 pub

除了裸 pub，还有几个常用刻度：

写法可见范围典型用途
无 pub当前模块及其后代内部实现，外部不需要知道
pub(super)父模块只给上一层用
pub(crate)整个 cratecrate 内部 API，不对外暴露
pub外部 crate（路径上每层都要可见）真正的公开 API
mod outer {
    pub(crate) mod inner {
        pub(crate) fn value() -> i32 { 7 }
    }
}

fn main() {
    println!("{}", outer::inner::value()); // 7：crate 内可见
}

pub(crate) 在固件里很有用：板级支持代码、协议打包这类“整个项目内部要用，但不打算给外部库用”的东西，用它比裸 pub 更收敛。

结构体和枚举的字段可见性另有规则（例如 pub struct 的字段默认仍是私有的），等结构体/枚举课再展开；今天先把模块和函数的边界打牢。

3. 路径三兄弟：crate / self / super

路径起点例子
crate::crate 根（main.rs / lib.rs）crate::protocol::build_magic_packet
self::当前模块self::parse_mac
super::父模块super::helper
标识符开头当前模块里的子项 / 同级项protocol::build_magic_packet

crate:: 是绝对路径；self:: / super:: 是相对路径。C 里没有模块，只有文件作用域和链接属性；Rust 的路径是模块树上的坐标，不依赖文件在哪。

3.1 use：只是当前作用域的快捷方式

mod outer {
    pub mod inner {
        pub fn value() -> i32 { 7 }
    }
}

use outer::inner; // 这个快捷方式只在 crate 根生效

mod consumer {
    pub fn read() -> i32 {
        inner::value() // E0433: cannot find module or crate `inner`
    }
}

fn main() {
    println!("{}", consumer::read());
}
error[E0433]: cannot find module or crate `inner` in this scope
（错误[E0433]：在当前作用域找不到模块或 crate `inner`）

use 只把名字引进**它所在的那一层作用域**，不会自动传给子模块。修法有两种：在 consumer 里自己写 use crate::outer::inner;，或者直接用全路径 crate::outer::inner::value()。use 也不改变可见性；它只是改名/建快捷方式，能不能访问仍由 pub 决定。

3.2 as、嵌套路径与 pub use

// as：同一个名字冲突时改名
use std::io::Result as IoResult;

// 嵌套路径：一行引入多个
use std::time::{SystemTime, UNIX_EPOCH};

pub use 是“导入 + 重新导出”：既把名字带进当前作用域，又把它放进当前模块的公开 API。rustlings modules2 就是它：

mod snacks {
    mod fruits {
        pub const PEAR: &str = "Pear";
    }

    pub use self::fruits::PEAR as fruit;
}

fn main() {
    println!("{}", snacks::fruit); // Pear
}

把 pub use 改成普通 use，fruit 就只在 snacks 内部可见，main 再访问 snacks::fruit 就会报私有错误。普通 use 是内部捷径；pub use 是对外门牌。

4. 文件模块：把房间搬到文件里

WoL 现在是一个 main.rs。把协议相关的东西搬到 src/protocol.rs，目录变成：

src/
├── main.rs
└── protocol.rs

src/main.rs：

mod protocol;

use protocol::{build_magic_packet, print_hex};

fn main() {
    let mac = String::from("AA-BB-CC-DD-EE-FF");
    let packet = build_magic_packet(&mac);
    print_hex(&packet);
}

src/protocol.rs：

const MAGIC_LEN: usize = 6;
const MAC_LEN: usize = 6;
const REPEAT: usize = 16;

pub const PACKET_LEN: usize = MAGIC_LEN + MAC_LEN * REPEAT;
const _: () = assert!(PACKET_LEN == 102);

fn parse_mac(mac: &str) -> Vec<u8> {
    mac.split('-')
        .map(|part| u8::from_str_radix(part, 16).unwrap_or(0))
        .collect()
}

pub fn build_magic_packet(mac: &str) -> [u8; PACKET_LEN] {
    let mac_bytes = parse_mac(mac);
    let mut packet = [0u8; PACKET_LEN];

    for b in &mut packet[..MAGIC_LEN] {
        *b = 0xFF;
    }

    for i in 0..REPEAT {
        let start = MAGIC_LEN + i * MAC_LEN;
        for j in 0..MAC_LEN {
            packet[start + j] = mac_bytes[j];
        }
    }

    packet
}

pub fn print_hex(packet: &[u8]) {
    for (i, &item) in packet.iter().enumerate() {
        print!("{:02X} ", item);
        if i % 16 == 15 { println!(); }
    }
    println!();
}

模块树对应关系：

crate（src/main.rs）
├── protocol（src/protocol.rs）
│   ├── PACKET_LEN（常量；外部要用再 pub）
│   ├── build_magic_packet（pub）
│   ├── print_hex（pub）
│   └── parse_mac（私有）
└── main
  • mod protocol; 声明模块；编译器去找 src/protocol.rs（旧式写法是 src/protocol/mod.rs，二选一）。
  • 不要在 protocol.rs 里再写 mod protocol；文件本身就是这个模块的内容。
  • parse_mac 只在 protocol.rs 内部使用，保持私有即可；build_magic_packet / print_hex 要给 main 用，标 pub。
  • PACKET_LEN 不必因为出现在公开函数的返回类型里就 pub：签名里的 [u8; PACKET_LEN] 对外就是 [u8; 102]，调用者不需要这个名字。只有外部代码也要用这个常量（比如声明同尺寸缓冲）时，才把它改成 pub。示例里保留 pub，是把它当作“公开的包长”；如果不需要，私有也可以。
  • mod 只加载一次，不是文本包含；不会出现 C 头文件那种重复定义。

嵌套模块时，文件路径跟着模块树走：protocol.rs 里写 pub mod packet;，子模块代码放 src/protocol/packet.rs。目录和树对齐，读代码时不用猜。

5. 固件视角：模块是硬件的边界

摇杆固件迟早会长成这样：

文件 / 模块职责对外
main.rs初始化、主循环不导出
buttons.rs按键扫描、消抖pub fn read()
usb.rsHID 上报pub(crate) 内部 API
packet.rs协议打包pub 或 pub(crate) 按需

模块边界的好处：

  • 隐藏实现：parse_mac、寄存器细节、缓冲区布局不必暴露给 main；
  • 限制耦合：想改内部实现时，只要公开 API 不变，其他模块不受影响；
  • 零运行期成本：模块只是编译期的命名空间和可见性检查，不会生成“模块对象”；
  • 读驱动源码的预演：Linux Rust 驱动也是按模块/文件组织，先习惯边界，后面读源码不迷路。
