第四课：闭包与迭代器——把循环写成流水线

第三课验收通过：first_word 的 WoL 实现正确，半开区间三理由已能脱离 first_word 复述，E0502 的“clear 交出所有权”已纠正为“可变借用与不可变借用重叠”，rustlings strings1–4 也过了。今天收的，是你其实已经用过、但还没命名的东西：vecs2 的 .iter().map(|x| x * 2).collect()、strings3 的 .iter().enumerate().rev()、Book 版 first_word 的 bytes.iter().enumerate()。今天只做一件事：把这三条链拆开，给每个零件命名——学完你能一眼读出“谁借用、谁拥有、谁在什么时候执行”。

1. 先看你写过的两条链

vecs2 里你已经写过这条：

// input: &[i32]，返回类型是 Vec<i32>
input.iter().map(|element| element * 2).collect()

逐段读：

  • iter()：返回一个迭代器（游标）；游标每次给你的元素是 &i32——借用原集合里的元素，不复制；
  • map(|element| ...)：这里的 |element| ... 就是闭包；element 是 &i32，闭包返回 i32；
  • collect()：把这条流水线的结果收进集合；具体收成什么，由函数返回类型 Vec<i32> 推断。

strings3 里你还写过这条：

// bytes: &[u8]
for (i, &b) in bytes.iter().enumerate().rev() { ... }
  • bytes.iter() 返回游标；游标每次给你的元素是 &u8；
  • .enumerate() 给每个元素配一个下标，游标的元素变成 (usize, &u8)；
  • .rev() 反向走；for (i, &b) 用模式把元组拆开：i 是下标，&b 把 &u8 拆成 u8。

这两条链里的两个主角，就是今天的闭包和迭代器。闭包是能记住环境的函数；迭代器是能一次次产出元素的值。 先把这两个名字记住，下面逐个拆。

2. 闭包：能记住环境的函数

先看一个最小例子，不急着背定义：

let n = 3;
let add_n = |x| x + n;    // |x| ... 就是闭包
println!("{}", add_n(5)); // 8

它看起来像函数，但多记住了一件事：n。闭包把“函数代码”和“它用到的外部变量”打包成一个值。下面再看 The Book 的正式定义。

The Book 的定义（原文已核实）：

Rust’s closures are anonymous functions you can save in a variable or pass as arguments to other functions.
（Rust 的闭包是可以保存在变量里、或作为参数传给其他函数的匿名函数。）

它和普通函数最大的差别：闭包能捕获定义处作用域里的值（capture values from the scope in which they’re defined）。C 里的函数指针只能带代码，不能带环境；闭包相当于“代码 + 一包捕获的数据”，编译器替你生成一个匿名类型来装这包数据。

// 普通函数：参数类型、返回类型都写出来
fn add_one(x: i32) -> i32 { x + 1 }

// 闭包：类型通常由上下文推断
let add_one = |x| x + 1;
let add_one_typed = |x: i32| -> i32 { x + 1 };

即使不捕获任何外部变量，|x| x + 1 这种匿名函数写法也叫闭包；捕获能力是它和普通函数的关键区别，但不是使用前提。你在 vecs2 里写的 |element| element * 2 就是没有捕获的闭包。

闭包怎么捕获，取决于闭包体里怎么用外面的值：

闭包体里怎么用捕获方式例子
只读 不可变借用 & let f = |x| x + factor;
修改 可变借用 &mut let mut inc = || count += 1;
消耗 / 移出闭包 拿走所有权 let f = move || name; 
let factor = 2;
let times = |x| x * factor;   // 不可变借用 factor
println!("{}", times(3));     // 6
println!("{factor}");         // factor 还能用

let mut count = 0;
let mut inc = || count += 1;  // 可变借用 count
inc();
inc();
println!("{count}");          // 2

let name = String::from("wol");
let consume = move || name;   // move：name 被移进闭包
// println!("{name}");        // E0382：name 已经不在外面了

move 是“强制按值捕获”的开关。线程、异步任务常要求 move，因为闭包可能比当前函数活得更久；这部分等到并发课再展开。

闭包也受借用规则约束。上面 inc 活着的时候，count 被它可变借用；只有 inc 最后一次使用之后，读 count 才不会冲突——这就是第二、三课的 NLL，只是这次借用发生在闭包里。

标准库还按“闭包能做什么”给它们分了三个 trait，今天只认门牌，不要求手写约束：

trait能力典型场景
Fn可多次调用，不修改、不消耗捕获值map 里的纯计算
FnMut可多次调用，可修改捕获值filter / 排序里的计数器
FnOnce只能调用一次，可消耗捕获值unwrap_or_else、线程的 move 闭包

所有闭包都实现 FnOnce；能力是叠加的：只读闭包三个都实现，会修改的只实现 FnMut 和 FnOnce，把捕获值移出去的只实现 FnOnce。迭代器的适配器大多收 FnMut，所以你在 map 里写闭包时不用操心这些名字。

3. 迭代器：一个 next() 的流水线

所有迭代器都实现标准库的 Iterator trait，核心只有一个方法：

pub trait Iterator {
    type Item;
    fn next(&mut self) -> Option<Self::Item>;
}

next() 每次给你一个元素，包在 Some(元素) 里；给完了返回 None。Option 就是“有 / 没有”的枚举，今天只需认得 Some 和 None 这两个变体，细节在枚举课展开。调用 next() 会改变迭代器的内部状态，所以它要 &mut self。

3.1 严格说，iter() 返回什么？

精度：iter() 返回的不是数组，也不是单个 &i32，而是一个迭代器对象——一个游标。完整说法是：“iter() 返回一个迭代器；这个迭代器每次 next() 产出的元素类型是 &i32”。不要把它误认成数组或单个引用。

游标内部通常保存“当前走到哪”和“到哪里停”的状态（具体是指针还是索引由实现决定，概念上就是游标）。每次 next()，它给你当前元素的引用，然后前进一格：

v:       [ 10 ][ 20 ][ 30 ]
              ^
it:      { 当前 → v[0], 结束 → 末尾之后 }

next() → Some(&v[0])     // 游标前进到 v[1]
next() → Some(&v[1])     // 游标前进到 v[2]
next() → Some(&v[2])     // 游标到达末尾
next() → None

注意：创建迭代器时，游标停在第一个元素之前；只写 v.iter() 不会给你任何元素。第一次 next()（或 for 循环第一轮）才取到第一个元素的引用，并且游标前进。

类型链（以 Vec<i32> 为例）：

let mut it = v.iter();    // it: 迭代器对象（游标），不是 &i32
let x = it.next();        // x: Option<&i32>
let first = x.unwrap();   // first: &i32，指向 v[0] 的数据

// &i32 指向数据，不指向游标；游标的内部指针/索引不暴露。

要手动调用 next()，迭代器变量必须声明为 mut；for 和 collect 会在内部把它变成可变的。iter().next() 可以写在临时值上，但 &iter().next() 是对临时 Option 取地址，不是对数据取地址——别这样写。

C 类比：iter() 像返回一个 struct { const int *p; const int *end; } 游标；next() 像 const int *next(struct iter *it)，走到末尾返回 NULL。Rust 把 NULL 换成了 None，把指针换成了 &i32。数组本身还是 v；游标只是借它走路。

C 里数组名传参会退化成指向首元素的指针，所以“数组”和“地址”经常混在一起；Rust 不搞这种隐式退化：Vec<i32> 是拥有型结构体，&[i32] 是“地址 + 长度”的胖指针，std::slice::Iter 是另一个游标结构体。

从一个集合拿到迭代器，有三种常见写法，差别全在所有权：

写法产出所有权集合之后还能用吗
v.iter()&T不可变借用能
v.iter_mut()&mut T可变借用借用结束后能
v.into_iter()T拿走所有权不能（E0382）

C 类比：iter() 像传一个只读指针；iter_mut() 像传可写指针；into_iter() 像把整个数组按值交给函数。

for 循环背后也是迭代器：for x in &v 走 &T，for x in &mut v 走 &mut T，for x in v 会调用 into_iter() 拿走 v。The Book 的说法是：循环接管迭代器，并在背后把它变成可变的（the loop took ownership of v1_iter and made it mutable behind the scenes）。

4. 适配器与消费者：流水线什么时候真的跑

The Book 原文（已核实）：

Iterators are lazy, meaning they have no effect until you call methods that consume the iterator to use it up.
（迭代器是惰性的：在你调用“消费”迭代器的方法把它用完之前，它什么也不做。）

map 不会在调用它的那一刻执行闭包。它把闭包和“怎么变换”记在迭代器里，等 collect / for / sum 来拉取时才逐个调用。map 的用途是“变换每个元素”，不是单纯遍历；只想遍历做副作用，用 for 或 for_each。

更准确地说：map 本身不跑循环。它把“上一个迭代器 + 闭包”包成一个新的迭代器（适配器）；真正的循环在消费者里——collect / for 反复调用 next()，每次拉取一个元素，Map 的 next() 才调用一次闭包。所以 map 包装的是迭代器，不是闭包；闭包只是它保存的变换函数。闭包被调用的次数由消费者实际拉取的元素数决定，不一定等于原容器长度（前面有 filter / take 时会更少；不消费就是 0 次）。

let v = vec![1, 2, 3];
let factor = 10;

let it = v.iter().map(|x| {
    println!("map 正在处理 {x}");
    x * factor
});
println!("map 构造完了，还没有 collect");

let out: Vec<i32> = it.collect();
println!("collect 完成：{out:?}");

输出顺序会先打印“map 构造完了”，再逐条打印“map 正在处理”，最后才是 collect 完成。这证明 map 只是登记，collect 才是启动器。

流水线上有两类方法，别混：

类别方法做什么什么时候执行
适配器（adapter）map每个元素变成新值懒：只登记，不执行
filter按条件保留元素懒：只登记，不执行
enumerate给每个元素加下标懒：只登记，不执行
rev反向遍历（需要双端迭代器）懒：只登记，不执行
消费者（consumer）collect收进集合执行整条链
sum求和执行整条链
for 循环逐个取元素执行整条链
v.iter()&i32 → .map(|x| x * 2)i32 → .filter(|x| *x > 3)闭包收到 &i32 → .collect()Vec<i32> 
let v = vec![1, 2, 3, 4];
let out: Vec<i32> = v.iter()          // &i32
    .map(|x| x * 2)                  // i32
    .filter(|x| *x > 3)              // filter 的闭包收到 &i32，要解引用
    .collect();                       // Vec<i32>
println!("{out:?}");                  // [4, 6, 8]

两个容易踩的点：

  • map 后面不接消费者，什么都不会发生；map 只是把“要做什么”记在迭代器里。
  • filter 会把“上一步产出的元素”以引用形式交给闭包。上一步是 i32，闭包参数就是 &i32，所以条件写 *x > 3；上一步是 &i32（比如 v.iter().filter(...)），闭包参数就是 &&i32。

collect 的目标类型由上下文决定，不是迭代器、也不是 collect 自己决定的。上面 let out: Vec<i32> 的标注就是上下文；如果只写 let out = ...collect();，编译器不知道你要收成什么，会报 E0283（type annotations needed）。collect 的作用是“消费整条链并把结果装进集合”，不是单纯做类型转换。

enumerate().rev() 还有一个细节：rev() 只改顺序，不改下标——[10, 20, 30].iter().enumerate().rev() 依次给你 (2, &30)、(1, &20)、(0, &10)。strings3 里手搓 trim 的右端下标，靠的就是这个“原始下标不重排”。

想逆序遍历，可以写 v.iter().rev().map(|x| x * factor).collect()；rev() 只改遍历顺序，不修改 v 本身。实测 v = [1, 2, 3]、factor = 10 时输出 [30, 20, 10]。v.iter().map(...).rev().collect() 也等价——两种顺序都行，前提是迭代器支持双端遍历（v.iter() 支持）。

The Book 还有一句值得记住（13.4 性能一节，原文已核实）：

Iterators are one of Rust’s zero-cost abstractions, by which we mean that using the abstraction imposes no additional runtime overhead.
（迭代器是 Rust 的“零成本抽象”之一：使用这层抽象不会带来额外的运行时开销。）

对固件尤其重要：map / filter / enumerate 只是编译期的描述，通常会被优化成和手写循环差不多的机器码；只有把结果 collect 到 Vec / String 这类拥有型集合，才会涉及分配，而 no_std 固件里没有堆，所以固件里更多用 for 直接消费迭代器，而不是 collect。

5. 用迭代器重写 first_word（Book 版）

第三课你写过索引循环版；The Book 4.3 的版本把循环交给迭代器：

fn first_word(s: &str) -> &str {
    let bytes = s.as_bytes();                    // &[u8]

    for (i, &item) in bytes.iter().enumerate() {
        // bytes.iter()      → &u8
        // .enumerate()      → (usize, &u8)
        // (i, &item) 模式   → i: usize，item: u8
        if item == b' ' {
            return &s[0..i];
        }
    }

    &s[..]
}

逐段读：as_bytes() 给出字节切片；iter() 借每个字节；enumerate() 加上原始下标；(i, &item) 把元组拆开，&item 再把 &u8 拆成 u8，所以下一行可以直接和字节字面量 b' ' 比较。

和你的索引版结果完全一样："Hello World" 返回 "Hello"，"Solo" 返回 "Solo"，空串返回空串。区别在读法：索引版手动维护 i 和 bytes.len()；迭代器版把“走到哪、下一个是谁”交给迭代器，代码里只剩“遇到空格就返回”。

6. WoL 实战预告：把 parse_mac 写成流水线

你现在的 parse_mac 是手动 push：

fn parse_mac(mac: &str) -> Vec<u8> {
    let mut bytes = Vec::new();
    for part in mac.split('-') {
        bytes.push(u8::from_str_radix(part, 16).unwrap_or(0));
    }
    bytes
}

用今天的两样东西，可以收成一条链：

fn parse_mac(mac: &str) -> Vec<u8> {
    mac.split('-')                                       // &str
        .map(|part| u8::from_str_radix(part, 16).unwrap_or(0))  // u8
        .collect()                                       // Vec<u8>
}

split('-') 产出每一段 &str；map 的闭包把一段变成 u8；collect 按返回类型收成 Vec<u8>。unwrap_or(0) 是骨架版的偷懒写法，正式版要报错——错误处理课再换。
