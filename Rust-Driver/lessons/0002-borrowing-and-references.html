第二课：借用与引用——数据不用送出去，可以借出去

验收通过：move_semantics 六个练习你全过了，move、Copy、Drop 已晋升进术语表。你在 move_semantics4 的笔记里问："可变借用只能有一次，语言的设计思想可能是'要用到的时候才借，借了尽快用'？"——这个直觉对了一半，这一课给你完整的答案。它是 Rust 并发安全的地基，也是你以后写多任务固件的第一道护栏。

1. move 的痛点：一送出去，就回不来了

第一课说过，把 String 传给函数 = 送走所有权。于是每个想"读一眼"的函数调用都变成了永别：

fn main() {
    let s1 = String::from("hello");
    let len = calculate_length(s1);   // s1 的所有权进了函数
    // println!("{s1}");               // 编译错误：s1 已经被移走，连打印都不配
    println!("长度是 {len}");
}

fn calculate_length(s: String) -> usize {
    s.len()
}   // s 在这里 drop，"hello" 没了；想再用 s1？没门

C 程序员的你立刻会想到：传指针不就行了？Rust 的答案是同一个思路，但带着编译器的全副武装——引用。函数只拿一张"参观证"，数据的主人不出门：

let len = calculate_length(&s1);   // 注意 &：借，不是送
println!("'{s1}' 的长度是 {len}");   // s1 毫发无损，照常使用

2. 引用：所有权的参观证

&T 叫不可变引用，&mut T 叫可变引用。创建引用的行为叫 borrowing（借用）。引用和 C 的指针长得像，但有一条本质区别：引用不拥有数据，所以绝不触发 drop——参观证到期，只是作废，房子还是原主人的，到不到期都轮不到参观证来拆。

《The Rust Programming Language》第 4 章把借用规则总结成两句话（原文已核实）：

1. At any given time, you can have either one mutable reference or any number of immutable references.（任意时刻，要么只有一个可变引用，要么有任意多个不可变引用。）
2. References must always be valid.（引用必须始终有效——不允许悬垂。）

规则 1 换成中文口诀：共享只读，或排他写，二选一。规则 2 是第 6 节的主题。

3. 不可变引用：多少人同时看都行

let mut s = String::from("hello");
let r1 = &s;        // 借一张参观证
let r2 = &s;        // 再借一张——可以，都是只读的
println!("{r1} 和 {r2}");   // 两个引用同时用，没问题
// r1、r2 的最后一次使用到此为止

这里藏着一个重要细节：引用的作用域不是到代码块结束，而是到最后一次使用（编译器管这个叫 NLL，非词法作用域）。上面这个例子，println! 之后 r1、r2 就"死"了——后面哪怕再来一个 &mut s 也不冲突。这解释了为什么"借用要短"：不是风格要求，是引用活着的区间天然只算到最后一次使用。

4. 可变引用：排他，且只有一个

let mut s = String::from("hello");
let r1 = &mut s;    // 排他写权限到手
let r2 = &mut s;    // 编译错误：cannot borrow `s` as mutable more than once at a time
                        //（同一时间不能把 s 借成可变引用超过一次）
r1.push_str(" world");

以及读写不能共存——只要只读引用还在用，可变引用就排不上号：

let r1 = &s;
let r2 = &s;
let r3 = &mut s;    // 编译错误：s 正被不可变借用着，不能同时借成可变
println!("{r1} {r2} {r3}");

现在回答你的问题：规则不是"借了尽快用"这种风格建议，而是编译期强制的排他访问——&mut T 活着的整个区间里，没有任何其他路径（变量或引用）能碰这块数据。为什么这么设计？The Book 给出了数据竞争的定义（原文已核实）：两个以上指针同时访问同一数据，至少其中一个在写，且没有同步机制。排他规则让这类错误在 Rust 里根本写不出来。你笔记里的直觉——"要用的时候才借"——是这条规则的实践面貌：因为引用活到最后一次使用，自然的写法就是短借短用。

兑现第一课的预告：&mut T 不是 Copy。第一课说过可变引用不能被复制——复制一份排他写权限就等于造出两条可写路径，正是规则要禁的东西。所以每个 &mut T 都是独一份，赋值即移动。

5. 实战：函数参数的三种传法

写法语义调用后原变量
f(s: String) 传本体move，所有权进函数失效
f(s: &String) 只读借borrow，函数只能看照常可用
f(s: &mut String) 可写借borrow，函数能改，但排他照常可用（借出期间你不能碰）

完整例子，注意 calculate_length 结束时 s（那个引用）出作用域什么都不 drop——它不是所有者：

fn main() {
    let s1 = String::from("hello");
    let len = calculate_length(&s1);
    println!("'{s1}' 的长度是 {len}");   // s1 从头到尾活着
}

fn calculate_length(s: &String) -> usize {
    s.len()
}   // s 出作用域，但它指向的 String 不属于它——不 drop，不释放

你在 vecs2 里写的 input.iter() 就是"借来遍历、不夺取所有权"——迭代器逐个把元素的引用交给闭包，原 Vec 一根汗毛都不少。.collect() 那段我们很快会有专门一课，现在认出"这是借用"就够了。

6. 悬垂引用：编译器替你挡的枪

规则 2 说"引用必须始终有效"。违反它长这样：

fn dangle() -> &String {
    let s = String::from("hello");
    &s            // 想把 s 的引用交出去
}   // 但 s 在这里 drop 了——引用指向一块已释放的内存：悬垂引用

// 编译错误 error[E0106]：this function's return type contains a borrowed value,
// but there is no value for it to be borrowed from
//（返回类型里含借来的值，但没有东西可借——没有主语的主人的句子）

这正是第一课 drop 模型的直接推论，你现在能自己讲明白了：引用必须比所有者短命。函数里的 s 出作用域就 drop，它借出去的引用却想活到函数外面—— Borrow Checker（借用检查器）静态扫描每一对"所有者-引用"的生命周期，这种事直接在编译期枪毙。修复方法也符合第一课的逻辑：把所有权交出去——返回 String 本体而不是引用。
