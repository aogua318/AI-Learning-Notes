第十课：生命周期——引用的有效期怎么标

本课路线：你其实已经用过生命周期：fn first_word(s: &str) -> &str 没写 'a 也能编译；fn describe() -> &'static str 直接返回字面量。今天把编译器替你做的省略展开：'a 是什么、什么时候必须写、结构体存引用怎么办、'static 到底承诺了什么。
判断标准：能读懂并写出 fn longest<'a>...，能解释 E0106 / E0515 / E0597，不再把 'static 当成“延长寿命”。

本课示例均用 rustc 1.99.1（edition 2021）实测；英文原文与报错附中文对照。代码里的中文注释是给你看的，不需要抄进最终项目。

0. 你已经在用生命周期

先看两个熟悉的签名：

  • fn first_word(s: &str) -> &str：返回值的引用来自 s；你没有写生命周期，编译器自动把返回值和 s 绑在一起。
  • fn describe() -> &'static str：返回字符串字面量；'static 表示这个借用在整个程序期间有效。

生命周期（lifetime）是编译期的标注，用来描述“这个引用能活多久、和谁的借用绑定”。它不是运行期字段，不会出现在结构体布局里，也没有运行期开销。

C 锚点：C 里返回指向局部变量的指针会悬垂，但编译器不一定拦；Rust 用生命周期标注让编译器在编译期检查引用的有效性。标注不是“延长寿命”，而是把“谁必须活得比谁久”写成契约。

1. 为什么需要生命周期：引用不能比 owner 活得久

1.1 返回局部变量的引用：E0515

fn bad() -> &'static str {
    let s = String::from("hi"); // s 拥有堆上的 "hi"
    &s                          // 借用 s 的内部数据
}

fn main() {
    println!("{}", bad());
}

s 在 bad 返回时被 drop；返回的引用会指向已经释放的数据。实测：

英文原文 
error[E0515]: cannot return reference to local variable `s`
returns a reference to data owned by the current function
中文对照
  • 不能返回指向局部变量 s 的引用。
  • 返回的是当前函数拥有的数据的引用；函数返回后数据被释放。

1.2 owner 先 drop，借用后使用：E0597

fn main() {
    let r;
    {
        let s = String::from("hi"); // s 只活到内层块结束
        r = &s;                     // r 借用 s
    }                               // s 在这里 drop
    println!("{r}");                // r 还在用，但 s 已经没了
}
英文原文 
error[E0597]: `s` does not live long enough
borrowed value does not live long enough
`s` dropped here while still borrowed
borrow later used here
中文对照
  • s 活不够久；被借用的值活不够久。
  • s 在仍被借用时就被丢弃，而借用稍后还要使用。

这两类问题都不能靠“写一个生命周期标注”解决：标注不能延长数据的寿命。正确方向是返回拥有所有权的值（如 String），或让 owner 活到引用最后一次使用之后。

2. longest：显式生命周期参数

2.1 完整程序

下面函数返回两个字符串中较长的那一个引用。它必须说明“返回值借用自 x 或 y，二者都要活够”：

fn longest<'a>(x: &'a str, y: &'a str) -> &'a str {
    // 读作：x、y、返回值都至少活到 'a；返回值不会超过较短的那个
    if x.len() > y.len() {
        x
    } else {
        y
    }
}

fn main() {
    let a = String::from("long string");
    let b = String::from("short");
    let r = longest(&a, &b);
    println!("{r}");
}

预期输出：

long string

2.2 'a 到底约束了什么

  • <'a> 是生命周期参数，像类型参数 <T> 一样在调用点填入。
  • x: &'a str、y: &'a str：x、y 都必须至少活到 'a。
  • -> &'a str：返回的引用也只能在 'a 内使用。
  • 实际调用时，'a 不会超过 x、y 两者中**较短的那个可用区间**；可以理解为两者的交集。
  • 它不是“x 的完整生命周期”，也不是“y 的完整生命周期”；它是一段两者都覆盖的时间。
名字类型生命周期说明
aStringmain 全程拥有自己的堆数据
bStringmain 全程拥有自己的堆数据
r&str'a = 两者中较短不能超过 a 或 b 的存活范围

类型链：

longest(&a, &b)
→ 'a = a、b 都还活着的区间
→ 返回 &'a str
→ r: &str 只能在这个区间内使用

2.3 不写生命周期：E0106

fn longest(x: &str, y: &str) -> &str {
    if x.len() > y.len() { x } else { y }
}

fn main() {
    println!("{}", longest("abcd", "123"));
}
英文原文 
error[E0106]: missing lifetime specifier
help: this function's return type contains a borrowed value,
      but the signature does not say whether it is borrowed from `x` or `y`
help: consider introducing a named lifetime parameter
      fn longest<'a>(x: &'a str, y: &'a str) -> &'a str
中文对照
  • 缺少生命周期标注。
  • 返回值含借用，但签名没有说明它借用自 x 还是 y。
  • 编译器建议引入命名生命周期参数 'a，并把三处都标上。

两个输入引用、一个返回引用时，编译器不能猜“返回的是哪一个”，所以必须显式写 'a。

2.4 返回值活不过较短的输入：E0597

把 main 改成下面这样（函数不变）：

fn main() {
    let a = String::from("long string");
    let r;
    {
        let b = String::from("xyz");
        r = longest(&a, &b);
    } // b 在这里 drop
    println!("{r}"); // r 可能借用 b，不能再用
}
英文原文 
error[E0597]: `b` does not live long enough
borrowed value does not live long enough
`b` dropped here while still borrowed
borrow later used here
中文对照
  • b 活不够久；被借用的值活不够久。
  • b 在仍被借用时被丢弃，而借用稍后还要使用。

把 println!("{r}") 移到内层块里（在 b drop 之前）就合法。这正是 longest 签名在保护的事：返回值不能超过较短输入。

精度补丁：如果函数永远返回 x，可以写成 fn first<'a>(x: &'a str, y: &str) -> &'a str，只把 x 绑到 'a。但 longest 可能返回 y，所以必须把 y 也绑到同一个 'a。

3. 省略规则：为什么 first_word 不用写 'a

3.1 完整程序

fn first_word(s: &str) -> &str {
    // 返回值借用自 s；省略规则把输出绑到 s
    for (i, b) in s.bytes().enumerate() {
        if b == b' ' {
            return &s[..i];
        }
    }
    &s[..] // 没有空格时返回整个 s
}

fn main() {
    let text = String::from("hello world");
    let word = first_word(&text);
    println!("{word}");
}

预期输出：

hello

3.2 省略规则

  1. 每个省略的输入生命周期各自成为一个参数。
  2. 如果恰好只有一个输入生命周期，返回值的省略生命周期 = 这个输入。
  3. 如果方法接收 &self 或 &mut self，返回值的省略生命周期 = self 的生命周期。
  4. 以上都不满足，返回值又含借用：必须显式写生命周期，否则 E0106。

first_word 等价于：

fn first_word<'a>(s: &'a str) -> &'a str

只有一个输入引用 s，所以规则 2 把输出绑到 s。而 longest 有两个输入引用，规则 2 不适用，必须显式写 'a。

3.3 借用检查的另一面：E0502

这里沿用 3.1 的 first_word，只改 main。

fn main() {
    let mut text = String::from("hello world");
    let word = first_word(&text);
    text.clear();          // 不可变借用 word 还活着
    println!("{word}");
}
英文原文 
error[E0502]: cannot borrow `text` as mutable
because it is also borrowed as immutable
immutable borrow occurs here
mutable borrow occurs here
immutable borrow later used here
中文对照
  • 不能可变借用 text，因为它已经被不可变借用。
  • first_word(&text) 的不可变借用要持续到 word 最后一次使用。
  • 把 text.clear() 放到 println!("{word}") 之后再试。

生命周期和借用检查是同一套机制的两面：生命周期说明“引用和谁绑定”，借用检查确保“绑定期间 owner 不被 move/drop/可变借用”。

4. 结构体持有引用：Book<'a>

4.1 完整程序

struct Book<'a> {
    author: &'a str,
    title: &'a str,
}

impl<'a> Book<'a> {
    fn new(author: &'a str, title: &'a str) -> Self {
        Self { author, title }
    }

    fn title(&self) -> &str {
        self.title // 省略规则 3：输出绑到 &self
    }
}

fn main() {
    let author = String::from("George Orwell");
    let title = String::from("1984");
    let book = Book::new(&author, &title);
    println!("{} by {}", book.title(), book.author);
}

预期输出：

1984 by George Orwell
  • Book<'a> 表示：这个 Book 实例不能比它借用的 author / title 活得更久。
  • impl<'a> Book<'a>：为带生命周期参数的 Book 实现方法；Self 就是 Book<'a>。
  • fn title(&self) -> &str：方法省略规则把返回值绑到 &self，也就是这个 book 的借用。
  • 结构体本身不拥有字符串数据；它借用外部字符串。

4.2 实例活过 owner：E0597

struct Book<'a> {
    author: &'a str,
    title: &'a str,
}

impl<'a> Book<'a> {
    fn new(author: &'a str, title: &'a str) -> Self {
        Self { author, title }
    }
}

fn main() {
    let book;
    {
        let title = String::from("1984");
        book = Book::new("George Orwell", &title);
    } // title 在这里 drop
    println!("{}", book.title); // book 还在借用 title
}
英文原文 
error[E0597]: `title` does not live long enough
borrowed value does not live long enough
`title` dropped here while still borrowed
borrow later used here
中文对照
  • title 活不够久；被借用的值活不够久。
  • title 在仍被借用时被丢弃，而借用稍后还要使用。
值生命周期说明
title内层块String 拥有数据
book期望用到 println 之后借用了 title，不能超过 title

如果结构体想拥有字符串，就用 String 字段，不需要生命周期参数；如果只是想借用，保留 &'a str 并接受“实例不能比 owner 活得久”的约束。

5. 'static：程序全程有效

5.1 完整程序

fn static_str() -> &'static str {
    "hello" // 字面量在二进制里，程序全程有效
}

static GREETING: &str = "hi"; // static 项的 &str 默认是 &'static str

fn main() {
    let a: &'static str = "literal";
    let b: &'static str = GREETING;
    println!("{a} {b} {}", static_str());
}

预期输出：

literal hi hello
  • &'static str 表示这个借用在整个程序运行期间都有效。
  • 字符串字面量、static 项的数据通常活到程序结束，所以可以得到 &'static str。
  • 'static 不是“延长寿命”的开关；它是对数据有效期的承诺。

5.2 局部数据不能冒充 'static

fn main() {
    let owned = String::from("hi");
    let r: &'static str = &owned; // owned 只活到 main 结束
    println!("{r}");
}
英文原文 
error[E0597]: `owned` does not live long enough
type annotation requires that `owned` is borrowed for `'static`
`owned` dropped here while still borrowed
中文对照
  • owned 活不够久。
  • 类型标注要求 owned 被借用 'static 那么久。
  • owned 在仍被借用时被丢弃。
别把两个概念混了：
static GREETING: &str = "hi"; 里的 static 是“固定地址的全局存储项”；
&'static str 里的 'static 是“借用有效期到程序结束”。
两者常一起出现，但不是同一件事。
进阶注脚：T: 'static 表示“T 不包含短借用的引用”，不是“T 的值永远不 drop”。String 满足 'static，但局部 String 仍会在作用域结束时 drop。Box<dyn Error> 默认也带 'static 约束；errors5 的错误类型都是自包含的，所以没问题。

6. 收束：错误编号与写法选择

错误典型场景修法
E0106 missing lifetime specifier多个输入引用、返回引用，或没有输入却返回引用显式写 <'a>，或返回拥有所有权的值
E0515 cannot return reference to local返回局部 String 的切片返回 String，或让调用者提供缓冲区
E0597 does not live long enoughowner 先 drop，借用后用；局部数据标成 'static让 owner 活到引用最后一次使用；不要冒充 'static
E0502 borrow overlap不可变借用还活着时可变借用 owner等借用最后一次使用之后再改
场景写法
返回入参的切片，只有一个输入引用fn f(s: &str) -> &str（省略规则 2）
多个输入中选一个返回fn f<'a>(x: &'a str, y: &'a str) -> &'a str
返回字面量 / static 数据-> &'static str
结构体借用外部字符串struct S<'a> { field: &'a str }
函数内部新造字符串返回 String，或写入调用者提供的缓冲区

三句话总结：

  1. 生命周期标注是编译期契约，不是运行期字段，也不能延长数据寿命。
  2. longest 的 'a 是“两个输入都还活着的那段”，所以返回值不能超过较短输入。
  3. 只有一个输入或方法是 &self 时，省略规则会把返回值绑到它；否则必须显式写生命周期。

常见误区：

  • “生命周期标注能让局部变量活到函数外” → 不能；E0515 / E0597 会拦住。
  • “'a 是运行期保存的年龄” → 是编译期参数。
  • “longest 要求 x、y 原本就是同一个生命周期” → 不要求；'a 取两者都覆盖的区间。
  • “结构体存引用不需要生命周期” → 需要 <'a>，实例不能超过被借用数据。
  • “'static 就是 static 变量” → 一个是生命周期，一个是存储项。
  • “返回 &str 就是 'static” → 只有字面量/static 才是；入参切片返回的是入参的生命周期。
