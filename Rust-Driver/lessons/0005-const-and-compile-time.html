第五课：const 与编译期常量——让编译器先算，让固件省内存

第四课验收通过：CP1–CP3 都完成了——闭包与迭代器的类型链、first_word 迭代器版、parse_mac 流水线，代码与运行输出都对。第一课留下的开放问题“const 到底特殊在哪”，今天收口。
开场先声明归属：const 是编译期求值；static 是运行期存在、但初始化在编译期；let 是运行期绑定。今天的目标很具体：看到一行声明，能说出它在编译期发生了什么、运行期有没有存储和地址、能不能出现在类型里。

本课示例均用 rustc 1.99.1（edition 2021）实测；英文原文后附中文对照。

1. 三种声明，三种归属

先看一个最小例子，不急着背定义：

fn main() {
    let n = 4;                     // 运行期绑定：语义上有一个变量
    const MAX: usize = 4;          // 编译期常量：使用处直接内联 4
    static GREETING: &str = "wol"; // 静态项：程序里恰好一份，有固定地址
    println!("{n} {MAX} {GREETING}");
}

let n 也可能被优化器折叠成 4，但那是优化，不是语言保证；const 的编译期求值是语言保证。这三者的差别可以压成一张表：

声明 求值 / 存在时机 存储与地址 能否用于数组长度 [u8; N] 典型用途
let n 运行期绑定（优化器可折叠，但无语言保证） 语义上有栈上的位置 不能，报 E0435 局部状态、循环变量
const N 编译期求值 不保证固定地址；使用处内联/复制 能 尺寸、协议长度、引脚号、寄存器地址
static N 初始化器在编译期求值；项本身运行期存在 固定地址、恰好一份 能（不可变且初始化器为常量时） 大查找表、需要地址、内部可变性
精度：实测 static N: usize = 4; let buf = [0u8; N]; 能编译。也就是说，const 与 static 都能出现在常量上下文里。它们的分界不是“能不能编译期用”，而是地址与份数：const 不保证固定地址、使用处可能被复制；static 保证程序里一份、所有引用同址。这个区别在固件里就是“立即数/内联”与“占一块内存”的区别。

1.1 C 锚点：Rust 的 const 更像 #define / constexpr

C 写法Rust 对应关键差别
#define MAX 4 const MAX: usize = 4; Rust 的 const 有类型、有作用域，不是文本替换
static const int TABLE[] = ...; static TABLE: [u8; N] = ...; 都有固定地址、一份；Rust static 的初始化器必须能在编译期算
const int max = 4; 没有直接对应 C 的 const 是只读对象，通常仍有存储；Rust const 是编译期值，不保证地址

所以你在 Rust 里写 const，先想 C 的 #define 或 C++ 的 constexpr；写 static，先想 C 里那个有地址的全局对象。不要把 C 的 const int 直觉直接搬到 Rust 的 const 上。

2. const：编译期值，使用处内联

const 的规则不多，但每条都硬：

  • 必须写类型：const N = 4; 报 missing type for `const` item（缺少 const 项的类型）；
  • 永远不可变：不能用 mut；
  • 初始化器必须是常量表达式：字面量、算术、其他 const、const fn 调用；不能是运行期函数调用、堆分配、运行时局部变量；
  • 可以写在任何作用域，包括函数体内；命名约定全大写加下划线。
const THREE_HOURS_IN_SECONDS: u32 = 60 * 60 * 3; // 编译期算成 10800
const PACKET_LEN: usize = 6 + 16 * 6;           // WoL 魔术包：102 字节

fn main() {
    const MAX: usize = 4;        // 局部 const 也合法，作用域只在 main 里
    let buf = [0u8; MAX];        // 数组长度是类型的一部分：buf: [u8; 4]
    println!("{} {PACKET_LEN}", buf.len());
}

The Book 对 const 的硬规则（原文已核实）：

“Constants are always immutable... the type of the value must be annotated... Constants may only be set to a constant expression, not to a value computed at runtime.”
（常量永远不可变……必须标注类型……只能赋值为常量表达式，不能赋值为运行期才计算出的值。）

const 的值会在使用处内联。Rust Reference 的原话（已核实）：

“Constants are essentially inlined wherever they are used, meaning that they are copied directly into the relevant context when used.”
（常量在使用处基本会被内联，也就是使用时直接复制进相关上下文。）

“References to the same constant are not necessarily guaranteed to refer to the same memory address.”
（对同一个常量的引用，不保证指向同一个内存地址。）

所以别把 const 当成“只有一份的全局变量”。要固定地址，用 static。这也是为什么大查找表通常用 static：const 在多个使用点可能各复制一份，static 保证只有一份。

2.1 为什么 let 不能当数组长度

let n = 4;
let buf = [0u8; n]; // E0435

编译器原文与翻译：

error[E0435]: attempt to use a non-constant value in a constant
（错误[E0435]：尝试在常量中使用非恒定值）
help: consider using `const` instead of `let`
（帮助：考虑用 const 代替 let）

关键不在“编译器不知道 n 等于 4”，而在数组长度是类型的一部分：[u8; 4] 和 [u8; 5] 是两个不同的类型。类型必须在编译期完全确定，所以长度必须是常量表达式。let n 是运行期绑定；哪怕优化器知道它是 4，类型检查器也不接受。

const 正好是“值层面的编译期保证”和“类型层面的定长需求”之间的桥。 这也是 Rust 没有 C99 那种变长数组（VLA）的原因之一：数组长度要么是编译期常量，要么改用 Vec / 切片。

3. static：有地址的那一份

static 是程序运行期间一直存在的一块固定分配。规则如下：

  • 初始化器在编译期求值；
  • 整个程序只有一份，所有引用和裸指针都指向同一块分配；
  • 生命周期是整个程序；程序结束时不会调用 Drop；
  • 不可变 static 可能被放进只读内存；可变 static 的读写需要 unsafe。
static MAGIC: [u8; 6] = [0xFF; 6];

fn main() {
    let a = &MAGIC;
    let b = &MAGIC;
    println!("{}", std::ptr::eq(a, b)); // true：同一个分配
}

Rust Reference 的保证（已核实）：

“All references and raw pointers to the static refer to the same allocation.”
（对这个 static 的所有引用和裸指针都指向同一块分配。）

std::ptr::eq 比较两个引用的地址；static 保证同一个分配，所以这里一定是 true。const 没有这个保证。

3.1 static mut：需要 unsafe 的全局可写状态

static mut COUNT: u32 = 0;

fn main() {
    // COUNT += 1; // E0133：读写 static mut 都需要 unsafe
    unsafe {
        COUNT += 1;
        let value = COUNT; // 复制出 u32，避免对 static 取引用
        println!("{value}");
    }
}

编译器原文与翻译：

error[E0133]: use of mutable static is unsafe and requires unsafe function or block
（错误[E0133]：使用可变 static 是不安全的，需要 unsafe 函数或块）

mutable statics can be mutated by multiple threads: aliasing violations or data races will cause undefined behavior
（可变 static 可能被多个线程修改：别名违规或数据竞争会导致未定义行为。）

Rust Reference 的原话（已核实）：

“For this reason, an `unsafe` block is required when either reading or writing a mutable static variable.”
（因此，读取或写入可变 static 都需要 unsafe 块。）

unsafe 不是“关掉检查”，而是“这段的安全性由你担保”。static mut 是全局可写状态，编译器无法证明没有别的线程或中断同时访问；数据竞争是未定义行为（undefined behavior，UB）。固件里遇到全局状态，优先考虑原子类型（AtomicU32 等）、临界区（critical section），或把状态收进一个所有者；不要一上来就 static mut。这些细节在并发与固件课展开，今天只要知道“它为什么危险”即可。

什么时候该用 static？Rust Reference 给了一个判断标准（已核实）：

“Constants should, in general, be preferred over statics unless one of the following are true: Large amounts of data are being stored. The single-address property of statics is required. Interior mutability is required.”
（一般应优先用常量而不是静态项，除非满足以下之一：要存大量数据；需要 static 的唯一地址性质；需要内部可变性。）

翻译成固件语言：小常量用 const；大查找表、需要固定地址的缓冲区用 static；需要运行期修改的全局状态，先想原子类型或临界区，而不是 static mut。

4. const fn 与编译期检查

const fn 是可以在编译期调用的函数。它也能在运行期调用；区别是它允许出现在常量上下文里。

const fn packet_len() -> usize {
    6 + 16 * 6
}

const PACKET_LEN: usize = packet_len(); // 编译期调用

fn main() {
    let buf = [0u8; packet_len()]; // 数组长度也能用 const fn
    let runtime_len = packet_len(); // 运行期调用同一个函数，也合法
    println!("{PACKET_LEN} {runtime_len} {}", buf.len()); // 102 102 102
}

const fn 里不能堆分配、不能调用非 const 函数、不能 async；if、loop、while 都可以。它不是“只能在编译期跑”，而是“可以在编译期跑”。如果初始化器里调用了普通函数，会报 E0015：

error[E0015]: cannot call non-const function `len` in constants
（错误[E0015]：不能在常量中调用非 const 函数 `len`）

4.1 const 上下文里的错误是编译错误

const N: usize = 4;
const BUF: [u8; N] = [0; N];
const FIRST: u8 = BUF[5]; // E0080：编译期就发现越界
error[E0080]: index out of bounds: the length is 4 but the index is 5
（错误[E0080]：索引越界：长度为 4，但索引是 5）

在普通运行期代码里，同样的索引会 panic；在 const 上下文里，编译器直接拒绝编译。溢出、断言失败、越界都属于 E0080 这一类。这是好事：错误在烧录前就被抓住。

4.2 编译期断言：给协议长度上护栏

const PACKET_LEN: usize = 6 + 16 * 6;
const _: () = assert!(PACKET_LEN == 102); // 不成立就 E0080

const _ 是匿名的常量项，只为了在编译期执行一个检查；assert! 在 const 上下文里可用。把 102 改成 101，cargo check 会直接报：

error[E0080]: evaluation panicked: assertion failed: PACKET_LEN == 101
（错误[E0080]：常量求值 panic：断言失败：PACKET_LEN == 101）

这就是固件里的“编译期护栏”：协议长度、缓冲区大小、寄存器位宽，写错就编译不过，不会等到上电才发现。

把今天见过的错误编号收成一张表，方便以后对照：

错误编号触发场景一句话

E0080const 求值越界 / 溢出 / 断言失败编译期就发现常量算不出来

5. 固件视角：为什么这课对摇杆重要

把今天的规则放回摇杆和网络检测盒：

  • 固定缓冲：const PACKET_LEN: usize = 102; let buf = [0u8; PACKET_LEN];——no_std 固件没有堆，包长必须在编译期定死，数组直接放在栈或静态区。
  • 寄存器 / 引脚常量：const PIN: u8 = 15;、const FLASH_BASE: usize = 0x1000_0000;——让地址有名字、有类型，编译器还能做常量折叠。
  • 大表：字模、键位映射、USB 描述符这类大数组，用 static 保证只有一份、地址固定；用 const 可能在多个使用点各复制一份。
  • 全局可变状态：static mut 需要 unsafe，中断 / 多任务下容易数据竞争；先用原子类型或临界区，后面并发 / 固件课展开。
需求首选
数组长度、协议长度、引脚号、寄存器地址const
大查找表、需要固定地址、FFI 共享static
运行期可改的全局状态原子类型 / 临界区 / 所有者持有，避免 static mut

内存归属一句话：小 const 更像“把值写进指令或立即数”，static 更像“在内存里占一块地”。固件里 Flash 和 RAM 是两本账，链接脚本决定 static 落在哪；只读 static 可能进 Flash 的只读段，可变 static 通常在 RAM。
