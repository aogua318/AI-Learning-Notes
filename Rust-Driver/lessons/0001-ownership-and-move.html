第一课：所有权——Rust 给驱动开发者的见面礼

老师的话：这是语言预备期的第一课。为什么从所有权开始？因为 Rust 的语法你八九成能从 C 和 Python 平移过来，所有权是唯一一件你从没见过的新东西。它也是整个 Rust 的地基——借用检查器、生命周期、智能指针，全部长在它上面。这一课只讲一件事：值从一个变量到另一个变量，到底发生了什么。

1. 为什么写驱动的人必须过这关

你有 C 背景，先对照你熟悉的三个现场：

你的现场C 的做法Rust 的做法
写固件（no_std，没有垃圾回收，常常连堆分配都没有） 手动 malloc/free，或干脆静态数组，靠人的纪律 所有权规则由编译器强制检查，违反就不让你编译
硬件外设（一个引脚只能被一个驱动用） 靠代码规范和注释约束，约束不住就是幽灵 bug 外设的所有权只能被取走一次，编译器替你独占
内核代码（double free、use-after-free 是 C 安全漏洞的常客） 靠 code review 和测试兜底 这两类错误在编译期直接消失

一句话概括：Rust 把内存管理从"人的纪律"变成了"编译器的规则"。而这条规则的全部内容，就是接下来这三条。

2. 三条规则

《The Rust Programming Language》第 4 章给出的所有权三规则，原文如下（出处链接）：

1. Each value in Rust has an owner.
2. There can only be one owner at a time.
3. When the owner goes out of scope, the value will be dropped.

翻译过来：每个值有且只有一个主人；主人换人（而不是多一个主人）的过程叫 move；主人离开作用域，值就被自动销毁。注意第二条——"同时只有一个"，这正是它和 C 分道扬镳的地方。

3. move：所有权的转移

先看 C 里你会怎么写一段"交接"堆内存的代码：

// C：把堆上传给你的搭档，然后两个人都以为自己是主人
char *s1 = strdup("hello");
char *s2 = s1;          // 浅拷贝：s1 和 s2 指向同一块堆内存
free(s1);               // 搭档 A 释放了
printf("%s", s2);       // 搭档 B 还在用 —— use-after-free
// 更糟的版本：s2 最后也 free 一次 —— double free

Rust 的写法：

let s1 = String::from("hello");   // 在堆上分配 "hello"，s1 是它的所有者
let s2 = s1;                        // move：所有权从 s1 转移给 s2
// 注意：堆数据一个字节都没动，被复制的只有栈上的"遥控器"三元组
// （指针、长度、容量）。s1 从此被标记为"已移动"，不再有效。

// println!("{s1}");                 // 编译错误：borrow of moved value: s1
println!("{s2}");                   // 只有 s2 能用

// 语法糖注释：println!("{s1}") 是 Rust 2021 的内联格式参数写法，
// 原始等价形式是 println!("{}", s1)。

move 防的就是上面 C 代码里的双重灾难：所有权一旦转移，旧变量立即失效，同一块内存不可能有两个"主人"，也就不可能 double free 或 use-after-free。旧变量不是被藏起来了，是编译器彻底不让你碰。

4. Copy：栈上类型的例外

如果值整个住在栈上、大小固定（比如一个 i32），"转移所有权"没有意义——直接按位复制一份，两个变量都有效。这类类型实现了 Copy trait：

let x = 5;
let y = x;                  // i32 实现了 Copy：按位复制，x 依然有效
println!("{x}, {y}");       // 输出：5, 5

let t = (1, true);          // 元组的所有成员都是 Copy，元组整体才是 Copy
let u = t;                  // t 依然有效

哪些类型是 Copy？The Book 列出的名单（已核实）：所有整数类型（如 u32）、bool、所有浮点类型（如 f64）、char，以及所有成员都是 Copy 的元组。String 这种堆上类型不是 Copy。

还有一条硬规矩（The Book 原文）：一个类型不能同时实现 Copy 和 Drop——因为 Copy 的意思是"赋值时复制一份、原变量照旧有效"，而 Drop 的意思是"作用域结束时自动释放资源"，两者同时成立就会重复释放。

5. 函数调用也是 move

move 不只发生在 let 赋值时。把值传给函数、从函数返回，规则完全一样：

fn take_ownership(s: String) {
    println!("{s}");
}   // s 在这里离开作用域，值被 drop —— 堆内存在这里释放

fn give_ownership() -> String {
    String::from("new")      // 这个值的所有权随返回值移交调用者
}

let s = String::from("hi");
take_ownership(s);           // move：s 的所有权进了函数
// println!("{s}");           // 编译错误：s 已经被移走了
let s2 = give_ownership();   // move：返回值的所有权交给 s2

对比 C：这相当于你传给函数的每一份堆内存都附带一次所有权交割，函数拿不走第二份，你也别想在交出去之后继续用。刚接触会觉得"处处受限于编译器"，但请记住第 1 节那张表：这些限制正在免费消灭一整类内核级漏洞。
