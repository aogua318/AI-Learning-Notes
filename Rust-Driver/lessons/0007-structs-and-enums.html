第七课：结构体与枚举——给固件数据建模

第六课已结课：WoL 已经拆成 main.rs + protocol.rs，模块与可见性 CP1–CP3 全部通过。今天从“函数和常量”进入“数据模型”：
结构体（struct）把相关字段装进一个值；枚举（enum）表示“几种形状之一”；impl 挂行为；match 把每种形状拆开处理。
C 锚点：struct 是 AND（同时拥有所有字段），enum 是 OR（只能是其中一种）；Rust 没有继承，组合靠字段和枚举。

本课示例均用 rustc 1.99.1（edition 2021）实测；英文原文与报错附中文对照。

1. 结构体：把相关字段装进一个值

#[derive(Debug)]
struct ButtonState {
    pin: u8,
    pressed: bool,
}

fn main() {
    let mut button = ButtonState {
        pin: 15,
        pressed: false,
    };

    button.pressed = true;
    println!("{button:?}");
}
  • 命名字段结构体：每个字段有名字和类型；用 结构体名 { 字段: 值 } 创建实例；用 . 访问字段。
  • 整个实例必须声明为 mut，Rust 不允许只把某个字段标成可变。
  • #[derive(Debug)] 让编译器生成 Debug 实现，所以能用 {:?} 打印；细节在 trait 课展开，今天先用它观察数据。
  • 字段名和变量名相同时可以简写：ButtonState { pin, pressed: false } 里的 pin 就是 pin: pin。

结构体更新语法：用旧实例的其余字段补全新实例：

let next = ButtonState {
    pressed: true,
    ..button
};
所有权：结构体拥有它的字段。更新语法里的 ..button 会像赋值一样移动/复制字段；如果字段是 String 这类非 Copy 类型，旧实例之后就不能整体再用。当前 ButtonState 的字段是 u8 / bool（都是 Copy），所以 button 还能用。

1.1 元组结构体与单元结构体

struct Pin(u8);      // 元组结构体：字段没有名字，用 .0 访问
struct Marker;       // 单元结构体：没有字段

fn main() {
    let pin = Pin(15);
    println!("{}", pin.0);

    let marker = Marker;
    println!("{:?}", marker); // 需要 #[derive(Debug)]
}
写法适用场景C 类比
命名字段结构体字段多、要可读性struct ButtonState { ... };
元组结构体新类型（newtype）、单位值、字段顺序就是语义typedef struct { ... } Pin; 的轻量版
单元结构体只做标记 / 挂 trait，不存数据空的标记结构体

Rust 结构体不需要 typedef，类型名直接可用；方法也不写在结构体大括号里，而是放到 impl 块。字段可见性仍受第六课规则约束：pub struct 的字段默认仍是私有的；本课都在同一模块里，先不展开。

2. impl：把行为挂到类型上

impl ButtonState {
    // 关联函数：没有 self，用 ButtonState::new(...) 调用
    fn new(pin: u8) -> Self {
        Self {
            pin,
            pressed: false,
        }
    }

    // 方法：&self，只读借用
    fn is_pressed(&self) -> bool {
        self.pressed
    }

    // 方法：&mut self，可变借用
    fn press(&mut self) {
        self.pressed = true;
    }
}
  • impl ButtonState { ... } 里的函数都关联到 ButtonState；一个类型可以有多个 impl 块。
  • Self 是 impl 后面那个类型的别名，这里就是 ButtonState。
  • 关联函数没有 self 参数，用 类型::函数(...) 调用；new 是最常见的构造器。
  • 方法的第一个参数是 self 的某种形式，用 实例.方法(...) 调用。
第一个参数权限典型用途
&self只读借用查询、计算，不改数据
&mut self可变借用修改字段
self取得所有权消耗并转换成别的东西（较少用）

这和第三课的“先看 self 签名”是同一张地图：&self 只读、&mut self 可改、self 拿走所有权。

let mut button = ButtonState::new(15);
println!("{}", button.is_pressed()); // false
button.press();
println!("{}", button.is_pressed()); // true

Rust 没有 C++ 的 -> 运算符；button.is_pressed() 会自动按方法签名加上 & / &mut（自动引用与解引用）。方法也可以定义在枚举上，后面会用到。

2.1 为什么 impl 不写在 struct 里

struct 只负责“数据长什么样”，impl 负责“这个类型能做什么”。两者是平级的 item；impl 不改变结构体的内存布局，也不会给每个实例存函数指针。

C 锚点：C 里是 struct ButtonState { ... }; 加自由函数 void button_press(ButtonState *b)；Rust 用 impl 把这些自由函数收进类型命名空间，换来方法调用语法：

button.press();
// 等价于全限定调用（UFCS）：
ButtonState::press(&mut button);
  • trait 实现必须独立写。impl Display for ButtonState { ... } 不能塞进 struct 大括号；#[derive(Debug)] 就是让编译器生成这样一个 impl。
  • 可以按功能拆成多个块。构造、查询、更新、打印可以各占一个 impl，便于阅读；大类型还能拆到同一 crate 的不同模块/文件里（但别的模块仍然不能访问私有字段）。
  • 支持泛型和条件实现。impl<T> Wrapper<T> 与 impl<T: Display> Wrapper<T> 可以分开写，后者只在 T: Display 时提供方法。
  • 数据与行为解耦。加方法不改变布局；没有继承，组合靠字段和枚举。trait impl 还受孤儿规则约束：类型和 trait 至少有一个属于当前 crate。

2.2 一个类型可以有多个 impl 块

可以，impl ButtonState { ... } 能出现多次；编译器把它们收集起来，方法查找在编译期完成，块与块的先后顺序不影响调用。

struct ButtonState {
    pin: u8,
    pressed: bool,
}

// 第一个 inherent impl：构造
impl ButtonState {
    fn new(pin: u8) -> Self {
        Self { pin, pressed: false }
    }
}

// 第二个 inherent impl：查询
impl ButtonState {
    fn is_pressed(&self) -> bool {
        self.pressed
    }
}

// trait impl：打印
impl std::fmt::Display for ButtonState {
    fn fmt(&self, f: &mut std::fmt::Formatter<'_>) -> std::fmt::Result {
        write!(f, "pin {} pressed {}", self.pin, self.pressed)
    }
}

两个 inherent 块里的方法都能直接调用：ButtonState::new(15)、b.is_pressed()；Display 实现让 println!("{b}") 可用。

两条冲突规则：
两个 inherent impl 里出现同名方法：error[E0592]: duplicate definitions with name `f`（重复定义）。
同一个 trait 对同一个类型实现两次：error[E0119]: conflicting implementations（实现冲突）。

inherent impl 必须和类型在同一个 crate；trait impl 受孤儿规则限制。

3. 枚举：一个值，几种形状

#[derive(Debug)]
enum ButtonEvent {
    Pressed { pin: u8 },
    Released { pin: u8 },
    Held { pin: u8, ms: u32 },
}
  • 枚举的值只能是其中一个变体：Pressed、Released、Held 三选一。
  • 每个变体可以带不同数量和类型的数据：前两个带一个 pin，Held 还带 ms。
  • 变体也分形状：Quit 是单元变体，Write(String) 是元组变体，Move { x, y } 是结构体变体。
  • 定义枚举会自动给每个变体生成构造器：ButtonEvent::Pressed { pin: 15 }。
struct 是 AND，enum 是 OR。 结构体实例同时拥有所有字段；枚举值只能是其中一个变体。需要“这几个字段总是一起出现”用结构体；需要“几种互斥形状之一”用枚举。

3.1 状态 vs 事件：三个变体不是三个状态

ButtonState.pressed 是状态（level）：现在按没按下，只有 true / false 两种。ButtonEvent 是事件（edge / change）：刚刚发生了什么。两者别混。

变体update 里的触发条件描述的是
Pressedpressed && !self.pressed从未按下变成按下的瞬间（上升沿）
Released!pressed && self.pressed从按下变成松开的瞬间（下降沿）
Held其余情况（状态没变）保持中；本次采样的 ms

同一次按键在时间线上的三个事件：

采样        (true,10)   (true,20)   (false,30)
上一状态     false       true        true
当前状态     true        true        false
事件         Pressed     Held        Released

所以 Pressed / Released 是边沿事件，Held 是持续事件；ms 是本次采样间隔，不是累计按住时长。为什么不用一个 bool？因为 bool 只说“现在按没按下”，说不出“刚刚按下”“刚刚松开”“已经按住多久”。

标准库的 Option<T> 就是枚举：

enum Option<T> {
    None,
    Some(T),
}

它表示“可能有值，也可能没有”。下一课的错误处理会正式讲 Option / Result；今天先知道：枚举不只会出现在你自己的代码里，标准库也用它表达“几种情况之一”。

4. match：把每种形状都处理掉

fn describe(event: ButtonEvent) {
    match event {
        ButtonEvent::Pressed { pin } => println!("pin {pin}: pressed"),
        ButtonEvent::Released { pin } => println!("pin {pin}: released"),
        ButtonEvent::Held { pin, ms } => println!("pin {pin}: held {ms} ms"),
    }
}
  • match 按顺序比较模式和值，命中第一个就执行对应分支。
  • 模式可以解构并绑定数据：Pressed { pin } 把变体里的 pin 绑到同名变量。
  • 必须穷尽所有变体；漏一个就报 E0004。这是 Rust 把“忘记处理某种情况”变成编译错误的地方。
  • _ 是通配符，表示“其余情况都归这里”；if let 只关心一种模式，代价是失去穷尽检查。
error[E0004]: non-exhaustive patterns: `ButtonEvent::Held` not covered
（错误[E0004]：模式不穷尽：没有覆盖 `ButtonEvent::Held`） 
// 只关心 Pressed：if let
if let ButtonEvent::Pressed { pin } = event {
    println!("pressed {pin}");
}

// 只关心一部分：match + 通配符
match event {
    ButtonEvent::Pressed { pin } => println!("pressed {pin}"),
    _ => println!("other event"),
}

match 是表达式，每个分支要返回同一种类型；分支代码多行时用大括号。C 的 switch 需要手动 break，Rust 的 match 不会“贯穿”，而且编译器检查穷尽。

4.1 拆开一条 match arm

ButtonEvent::Pressed { pin }   =>   println!("pin {pin}: pressed"),
└──────── 模式 ────────┘        └──────── 分支表达式 ────────┘
  • ButtonEvent::Pressed { pin } 是模式，不是构造值：它匹配 Pressed 变体，并把字段 pin 绑到一个新变量 pin。长写法是 Pressed { pin: pin }，冒号左边是字段名，右边是绑定名；{ pin } 是字段简写。
  • => 是 match arm 的语法规则；, 分隔各条 arm。
  • println!("pin {pin}: pressed") 里的 {pin} 是行内格式捕获（Rust 2021），等价于 println!("pin {}: pressed", pin)，属于语法糖；println! 本身是宏。

长写法对照：

ButtonEvent::Pressed { pin: pin } => println!("pin {}: pressed", pin),
模式绑定的所有权：pin: u8 是 Copy，模式绑定只复制一个字节，原事件还能用。若字段是 String，Pressed { pin } 会把 String 移出来，事件变成“部分移动”，之后再用报 E0382（借用已部分移动的值）。

4.2 执行顺序

fn describe 只是定义，函数体不会在定义时执行；match event 在 describe(...) 被调用时才运行。顺序是：

  1. describe(x) 把 x 按值传进参数 event；ButtonEvent 没有 Copy，这里发生移动。
  2. 进入函数体，match event 求值被匹配的值（只求一次）。
  3. 从上到下试模式，第一个匹配的 arm 执行，其余不执行；C 的 switch 需要 break，Rust 不会贯穿。
  4. 执行 arm 的表达式；所有 arm 必须返回同一种类型，这里 println! 返回 ()。
  5. match 是表达式，整个 match 的值就是选中 arm 的值。

穷尽检查是编译期，选中哪个分支是运行期。漏掉变体不是运行到 default，而是编译期 E0004。

课程第 4 节的 describe 只是示例，后面的 main 没有调用它；真正执行的是第 5 节 main 里内联的 match button.update(...)。两者结构一样，只是一个包在函数里，一个直接写在循环里。

5. 固件视角：按键状态与事件

摇杆固件里，按键不只是一个 bool，而是一串事件：按下、保持、松开。用结构体存状态，用枚举表达事件，用 match 处理：

#[derive(Debug)]
struct ButtonState {
    pin: u8,
    pressed: bool,
}

#[derive(Debug)]
enum ButtonEvent {
    Pressed { pin: u8 },
    Released { pin: u8 },
    Held { pin: u8, ms: u32 },
}

impl ButtonState {
    fn new(pin: u8) -> Self {
        Self {
            pin,
            pressed: false,
        }
    }

    fn update(&mut self, pressed: bool, ms: u32) -> ButtonEvent {
        if pressed && !self.pressed {
            self.pressed = true;
            ButtonEvent::Pressed { pin: self.pin }
        } else if !pressed && self.pressed {
            self.pressed = false;
            ButtonEvent::Released { pin: self.pin }
        } else {
            ButtonEvent::Held {
                pin: self.pin,
                ms,
            }
        }
    }
}

fn main() {
    let mut button = ButtonState::new(15);

    for (pressed, ms) in [(true, 10), (true, 20), (false, 30)] {
        match button.update(pressed, ms) {
            ButtonEvent::Pressed { pin } => println!("pin {pin}: pressed"),
            ButtonEvent::Released { pin } => println!("pin {pin}: released"),
            ButtonEvent::Held { pin, ms } => println!("pin {pin}: held {ms} ms"),
        }
    }
}

输出：

pin 15: pressed
pin 15: held 20 ms
pin 15: released
课程版的简化：update 的 else 同时接住了 true/true 和 false/false，所以刚初始化的按钮喂 (false, 10) 也会得到 Held。严格说 Held 只应在上一次和这一次都按下时发；false/false 应是“无事件”。本课为了避开 Option 先这样写；CP3 按课程版实现即可，知道这个边界即可。

为什么用枚举而不是一个带 pressed / released / held 三个 bool 的结构体？因为三个 bool 能组合出“同时 pressed 又 released”这种非法状态；枚举只允许三选一，match 又强迫你处理每一种。C 里常用“tag + union”模拟这种安全枚举；Rust 的 enum 把这个模式做成了语言内建，并自动检查穷尽。
