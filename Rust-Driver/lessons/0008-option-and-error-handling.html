第八课：Option 与错误处理——把缺失和失败写进类型

第七课已结课：button-model 能输出 pressed / held / released。第七课留下两个尾巴：
① update 在 false/false 时只能硬塞一个 Held；
② parse_mac 用 unwrap_or(0) 把坏 MAC 静默变成 0。
今天用标准库的两个枚举收口：Option<T> 表示“可能有、可能没有”，Result<T, E> 表示“成功、或者失败并带原因”，? 把错误向上传。
C 锚点：Option ≈ 一个必须检查的 tag + 值；Result ≈ 返回码 + 错误值——区别是编译器强制你处理。

本课示例均用 rustc 1.99.1（edition 2021）实测；英文原文与报错附中文对照。

1. Option：把“没有”写进类型

第七课已经见过它：标准库里的 Option 就是一个枚举。

enum Option<T> {
    None,
    Some(T),
}

T 是类型参数（type parameter），先把它理解成“占位符”：Option<u8> 里的 T 是 u8，Option<ButtonEvent> 里的 T 是 ButtonEvent。泛型课会正式展开。今天只要会读这两种写法。

Option 的值只有两种：Some(值) 或 None。它不是空指针；None 是一个正常的枚举值，必须用 match、if let 或方法处理。

1.1 把 button-model 的 false/false 收口

第七课的 update 返回 ButtonEvent，所以“没有事件”时只能返回一个勉强的 Held。把返回类型改成 Option<ButtonEvent>，没有事件就返回 None：

#[derive(Debug)]
struct ButtonState {
    pin: u8,
    pressed: bool,
}

#[derive(Debug)]
enum ButtonEvent {
    Pressed { pin: u8 },
    Released { pin: u8 },
    Held { pin: u8, ms: u32 },
}

impl ButtonState {
    fn new(pin: u8) -> Self {
        Self {
            pin,
            pressed: false,
        }
    }

    fn update(&mut self, pressed: bool, ms: u32) -> Option<ButtonEvent> {
        if pressed && !self.pressed {
            self.pressed = true;
            Some(ButtonEvent::Pressed { pin: self.pin })
        } else if !pressed && self.pressed {
            self.pressed = false;
            Some(ButtonEvent::Released { pin: self.pin })
        } else if pressed {
            Some(ButtonEvent::Held { pin: self.pin, ms })
        } else {
            None
        }
    }
}
fn main() {
    let mut button = ButtonState::new(15);

    for (pressed, ms) in [(false, 10), (true, 20), (true, 30), (false, 40)] {
        match button.update(pressed, ms) {
            Some(ButtonEvent::Pressed { pin }) => println!("pressed {pin}"),
            Some(ButtonEvent::Released { pin }) => println!("released {pin}"),
            Some(ButtonEvent::Held { pin, ms }) => println!("held {pin} {ms} ms"),
            None => println!("no event"),
        }
    }
}

输出：

no event
pressed 15
held 15 30 ms
released 15
  • false/false 不再伪装成 Held：没有事件就是 None。这是对第七课简化的正式收口。
  • match 的模式可以嵌套：外层 Some 剥掉 Option，内层 ButtonEvent::Pressed { pin } 读枚举 tag 并绑定字段。
  • 返回类型变成 Option<ButtonEvent> 后，调用者必须处理 None；漏掉就是 E0004（非穷尽模式）。把“可能没有”写进类型，编译器就会替你检查。
类型链：button.update(true, 20) → Option<ButtonEvent> → 本刻返回 Some(ButtonEvent::Held { pin: 15, ms: 20 })。函数签名先告诉你“可能没有”，再让你决定怎么处理。

1.2 if let、while let 与嵌套 Option

接着上面的 button：

let event = button.update(true, 10);
if let Some(ButtonEvent::Pressed { pin }) = event {
    println!("pressed {pin}");
}

let mut stack = vec![1, 2, 3];
while let Some(top) = stack.pop() {
    println!("{top}");
}
  • if let 只关心一个模式；没有 else 时，其余情况直接跳过，不要求穷尽。
  • while let 在模式不再匹配时结束循环。Vec::pop() 返回 Option<T>：空 Vec 返回 None。

嵌套 Option 需要嵌套模式。下面这个 Vec 的元素本身就是 Option<i8>：

let mut items: Vec<Option<i8>> = vec![Some(1), None, Some(3)];

while let Some(Some(n)) = items.pop() {
    println!("n = {n}");
}

输出只有一行 n = 3。因为 items.pop() 的返回类型是 Option<Option<i8>>：外层表示 Vec 空没空，内层表示元素本身是不是 None。模式里的 Some 层数要和类型层数对上；遇到 None 元素时模式不匹配，循环就停，后面的 Some(1) 不会被处理。

1.3 常用方法：先看接收者

方法接收者None 时用途
map(f)selfNoneSome(x) → Some(f(x))，只转换内部值
unwrap_or(d)self返回 d给默认值，不 panic
ok_or(e)selfErr(e)转成 Result，补一个错误值
as_ref()&selfNone借用内部值，不移动原 Option
unwrap()selfpanic只在确定有值时用（下一节）
let n: Option<u8> = Some(7);
println!("{:?}", n.map(|v| v + 1));   // Some(8)
println!("{}", n.unwrap_or(0));       // 7

let missing: Option<u8> = None;
println!("{}", missing.unwrap_or(0)); // 0

let as_result: Result<u8, &str> = missing.ok_or("missing");
println!("{as_result:?}");            // Err("missing")

注意接收者：map / unwrap_or / ok_or / unwrap 都按值拿 self，会消耗 Option；as_ref 只借用。第七课的口诀继续有效：先看 self 签名，再问会不会 move。

2. Result：把“失败原因”写进类型

Option 能说“没有”，但说不出“为什么没有”。解析 MAC 失败可能是长度不对，也可能是某一段不是十六进制；这两种情况调用者要分别处理，就用 Result<T, E>。

enum Result<T, E> {
    Ok(T),
    Err(E),
}
fn main() {
    let good = "FF".parse::<u8>();
    let bad = "ZZ".parse::<u8>();
    println!("{good:?}");
    println!("{bad:?}");
}

输出：

Ok(255)
Err(ParseIntError { kind: InvalidDigit })

"FF".parse::<u8>() 的返回类型是 Result<u8, ParseIntError>。失败不是异常，是一个装着错误值的普通返回值；ParseIntError 是标准库的错误类型，现在用 {:?} 打印即可。

match "FF".parse::<u8>() {
    Ok(v) => println!("ok {v}"),
    Err(e) => println!("bad hex: {e}"),
}

2.1 自定义错误：MacError

错误原因有限、互斥时，最适合用枚举表示：

#[derive(Debug)]
pub enum MacError {
    Length,
    NonHex,
}

fn parse_mac(mac: &str) -> Result<[u8; 6], MacError> {
    let parts: Vec<&str> = mac.split('-').collect();
    if parts.len() != 6 {
        return Err(MacError::Length);
    }

    let mut bytes = [0u8; 6];
    for (i, part) in parts.iter().enumerate() {
        bytes[i] = u8::from_str_radix(part, 16)
            .map_err(|_| MacError::NonHex)?;
    }
    Ok(bytes)
}
  • MacError 只有两种原因：段数不对（Length）、某段不是十六进制（NonHex）。“原因有限且互斥”正是 enum 的主场。
  • #[derive(Debug)] 让错误能打印；main 返回 Result 时也要求错误类型实现 Debug（后面会看到）。
  • map_err(|_| MacError::NonHex) 只改错误，不改成功值：Result<u8, ParseIntError> → Result<u8, MacError>。
  • 末尾的 ? 把 Err(MacError::NonHex) 提前返回；成功则把 u8 赋给 bytes[i]。
类型回答的问题成功失败 / 缺失典型场景
Option<T>有没有值？Some(T)None（没有原因）查找、pop、空切片 first()
Result<T, E>成功还是失败？为什么？Ok(T)Err(E)（带原因）解析、I/O（输入输出）、校验

两者可以互相转换：Option::ok_or / ok_or_else 把 None 补成 Err；Result::ok() 丢弃错误信息，变成 Option。

3. unwrap / expect：panic 的边界

unwrap / expect 是“我确定它成功”的断言；失败时 panic（运行期），不是编译错误。

let n: Option<u8> = None;
println!("{}", n.unwrap());
thread 'main' panicked at src/main.rs:3:22:
called `Option::unwrap()` on a `None` value
note: run with `RUST_BACKTRACE=1` environment variable to display a backtrace

中文对照：在 None 值上调用了 Option::unwrap()；程序以退出码 101 结束。expect("...") 的 panic 消息会换成你给的文字，方便定位。

  • 可以用：测试、示例、原型；或值由代码自己保证（例如硬编码常量），并用 expect 写清理由。
  • 不要用：外部输入（用户、网络、文件、命令行参数）。这些失败是可预期的，应该返回 Result，让调用者决定重试、报错还是忽略。
  • Book 9.3 的判据：坏状态是“意外”的，且继续运行不安全时 panic；能预期、能恢复的失败，返回 Result。
  • 固件里更要谨慎：no_std 程序的 panic 通常直接停机；协议解析失败应交给上层处理。

旧版 parse_mac 的问题不是 panic，而是静默吞错：

// 旧版：解析失败时给 0
let b = u8::from_str_radix(part, 16).unwrap_or(0);

unwrap_or(0) 不 panic，但会把坏输入变成合法字节 0x00；魔术包照样 102 字节，看起来成功，实际 MAC 错了。静默错误比 panic 更难查，这正是要改成 Result 的原因。

另外，unwrap 的接收者是 self，会移动原 Option：

let name = Some(String::from("Ada"));
let n = name.unwrap();
println!("{n}");
// println!("{name:?}"); // 取消注释会报 E0382
error[E0382]: borrow of moved value: `name`
note: `std::option::Option::<T>::unwrap` takes ownership of the receiver `self`, which moves `name`

中文对照：借用已移动的值；unwrap 取得接收者 self 的所有权，name 被移走。需要保留原 Option 时写 name.as_ref().unwrap()：as_ref 只借用，得到 Option<&String>。

4. ?：错误的早退

把错误一层层往上交，match 会写得很啰嗦；? 是它的简写：

fn parse_port(s: &str) -> Result<u16, std::num::ParseIntError> {
    let port = s.parse::<u16>()?;
    Ok(port)
}

fn main() {
    println!("{:?}", parse_port("8080"));
    println!("{:?}", parse_port("http"));
}

输出：

Ok(8080)
Err(ParseIntError { kind: InvalidDigit })

? 放在 Result 后面：Ok(v) 取出 v 继续；Err(e) 立刻从当前函数返回 Err(e)。它大致展开成：

let port = match s.parse::<u16>() {
    Ok(v) => v,
    Err(e) => return Err(e),
};

更准确地说，返回的是 Err(From::from(e))：函数错误类型与表达式错误类型不同时，? 会用 From 自动转换。上一节的 MacError 还没实现 From<ParseIntError>，所以先用 map_err 手动转好；trait 课会讲怎么自己实现 From。

? 对 Option 也适用：Some(v) 取出 v，None 直接 return None；但它只能用在返回 Option 的函数里。

返回类型必须匹配。在返回 () 的函数里用 ?：
error[E0277]: the `?` operator can only be used in a function that returns `Result` or `Option` (or another type that implements `FromResidual`)
中文对照：错误[E0277]：? 运算符只能用在返回 Result 或 Option（或其他实现 FromResidual 的类型）的函数里。

在返回 Result 的函数里对 Option 用 ?：
error[E0277]: the `?` operator can only be used on `Result`s, not `Option`s, in a function that returns `Result`
中文对照：在返回 Result 的函数里，? 只能用于 Result，不能用于 Option。编译器提示用 .ok_or(...)? 补一个错误值，转成 Result。

反过来，返回 Option 的函数里对 Result 用 ?，同样报 E0277；可以用 .ok()?，但错误原因会被丢掉。

4.1 main 也可以返回 Result

build_magic_packet 在下一节改造，这里先看 main 的返回类型：

fn main() -> Result<(), MacError> {
    let packet = build_magic_packet("AA-BB-CC-DD-EE-FF")?;
    println!("packet len = {}", packet.len());
    Ok(())
}
  • 成功时要写 Ok(())；失败时 Err(e) 会打印 Error: {e:?}（Debug 格式），并以非 0 退出码结束。
  • 错误类型必须实现 Debug；否则 Result<(), E> 不满足 Termination，报 E0277：
error[E0277]: `MacError` doesn't implement `Debug`
note: required for `Result<(), MacError>` to implement `Termination`

中文对照：MacError 未实现 Debug；main 的返回类型需要实现 Termination（程序入口的终止协议 trait），而 Result<(), E> 只有在 E: Debug 时才实现它。

编译期 vs 运行期：? 的展开、返回类型检查、From 约束都在编译期；真正走 Ok 还是 Err、打印什么错误、退出码是多少，在运行期。它不是异常，也不会栈展开。

5. 固件视角：WoL 的 parse_mac 不再吞错

把本课学的东西落到 WoL 项目上。改造前后：

位置旧版新版
parse_mac 返回Vec<u8>Result<[u8; 6], MacError>
坏输入unwrap_or(0)，静默变成 0Err(Length) / Err(NonHex)
build_magic_packet直接返回 [u8; 102]Result<[u8; 102], MacError>，内部用 ?
main无返回值Result<(), MacError>，用 ?
pub fn build_magic_packet(mac: &str) -> Result<[u8; PACKET_LEN], MacError> {
    let mac_bytes = parse_mac(mac)?;
    // ... 其余填包逻辑不变 ...
    Ok(packet)
}

其余填包逻辑不变：只在开头用 ? 拿到 6 个字节，末尾用 Ok(packet) 包起来。错误会沿着 parse_mac → build_magic_packet → main 一路往上，直到有人决定怎么处理。

错误类型也要可见。build_magic_packet 是公开函数，MacError 出现在它的返回类型里，所以 MacError 必须也是 pub。否则编译器报 type `MacError` is private（类型 `MacError` 是私有的），或给出 private_interfaces 警告（私有类型出现在公开接口里）。这是第六课可见性规则的延续：公开 API 里出现的类型，至少要一样公开。

正常运行（MAC 正确）：

$ cargo run
目标 MAC：AA-BB-CC-DD-EE-FF
FF FF FF FF FF FF AA BB CC DD EE FF ...
（共 102 字节）

把 MAC 改成 AA-BB-CC-DD-EE：

$ cargo run
Error: Length
# 退出码 1

改成 AA-BB-CC-DD-EE-ZZ 会得到 Error: NonHex。两种错误都由调用者决定怎么处理，解析函数本身不 panic。

  • Result 定义在 core 里，no_std 固件也能用；MacError 这种小 enum 不占堆。
  • 固件里 panic 通常直接停机，所以协议解析一律返回 Result，让上层决定重试还是上报。
  • 还有一处遗留：parse_mac 里的 Vec<&str> 需要堆分配。PC 端 CLI 没问题；固件版要改成无分配写法（例如先数 split('-') 的段数，再逐段填数组），留到固件课。
