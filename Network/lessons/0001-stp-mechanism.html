第一课：STP 机制——环路、选举与端口角色

这一课只拿一个东西：看到一张交换机拓扑图，能算出谁是 root、哪个端口被阻塞、为什么。你每天都在配 stp priority、stp mode，学完就知道配下去之后，网络里实际在发生什么。

1. 为什么需要 STP：环路的两个后果

冗余链路是必要的——一条链路断了，流量还能走另一条。但以太网交换机转发帧时不看生存时间：IP 包有 TTL，以太网帧没有。于是一个帧只要进了环，就会被每台交换机无休止地复制转发。后果有两个：

后果机制
广播风暴（broadcast storm）广播帧、组播帧、目的 MAC 未知的单播帧都会被交换机泛洪。环里的泛洪互相叠加，指数级复制，几十秒占满整条链路带宽，正常业务全部瘫痪
MAC 地址表抖动（MAC table flapping）同一个源 MAC 的帧会从环的不同端口被各交换机「学到」，表项反复刷新、反复失效，交换机忙于更新地址表，转发起伏不定

STP（Spanning Tree Protocol，生成树协议）的解法一句话：逻辑上堵掉一部分端口，把环拆成树。物理链路一条不少（冗余还在），逻辑上无环（风暴消失）。

一句话记忆：STP 不是「关掉备份链路」，是「让备份端口待命」——主路径断了，它立刻顶上来。

2. BPDU：交换机之间的选票

交换机之间靠 BPDU（Bridge Protocol Data Unit，桥协议数据单元）协商。root 桥每 2 秒（Hello Time）发出一次配置 BPDU（Configuration BPDU），非 root 桥收到后，把自己的信息写进去再往下游传——BPDU 每过一台交换机，路径开销就累加一次。

BPDU 里的关键字段：

字段作用
Root ID发送者当前认定的 root 桥 ID（选票投给谁）
Root Path Cost发送者到 root 的累计路径开销（我离 root 有多远）
Bridge ID发送这个 BPDU 的桥自己的 ID（我是谁）
Port ID发送 BPDU 的端口（我从哪个口发出的）
Message Age / Max Age / Hello Time / Forward Delay计时器：BPDU 寿命、老化上限、心跳间隔、端口状态迁移的等待时间

拓扑发生变化时（链路 up/down），交换机会发 TCN BPDU（Topology Change Notification，拓扑变化通知）通知 root，触发地址表老化加速——细节第三课之后用到时再展开，现在只要知道「BPDU 是 STP 世界里唯一的语言」。

3. 选 root：比小不比大

每台交换机的 Bridge ID（桥 ID）由两部分拼成：

Bridge ID = 优先级（2 字节，默认 32768，只能取 4096 的倍数）+ 交换机 MAC 地址

全网交换机交换一轮 BPDU 后，Bridge ID 最小的那台成为 root bridge（根桥）。优先级相同时比 MAC 地址。root 是整棵生成树的「树根」，所有路径开销都以到它的距离计算。

实践含义：核心交换机应该当 root。华为设备上两条路——直接指定优先级（stp priority 0，0 是最高优先级），或用 stp root primary 让设备自动算一个足够低的优先级。如果 root 选错了（比如一台接入层小交换机当了 root），主干流量全要绕到它那里，网络又慢又脆。

4. 端口角色：每个端口回答三个问题

root 选出来之后，每个端口要回答三个问题，答案决定它的角色：

问题一：谁到 root 最近？每台非 root 交换机选出 root port（根端口，RP）——收到的 BPDU 里 Root Path Cost 最小的那个端口。平手时依次比：对端 Bridge ID → 对端 Port ID → 本端 Port ID。root 桥自己不需要 RP。

问题二：这个网段谁说了算？每个网段（每条链路的两端之间）选出一个 designated port（指定端口，DP）——该网段上到 root 开销最小的端口。平手时比 Bridge ID，小者胜出。root 桥的所有端口都是 DP。

问题三：剩下的怎么办？既不是 RP 也不是 DP 的端口进入 blocking（阻塞）状态——不收发数据帧。

精度点（很多人在这里含糊）：阻塞端口不是链路 down。它的物理链路是 UP 的，照常收发 BPDU，只是不转发数据帧。它是「热备份」：主路径一断，它立刻接管。你在诊断题里答的「down 掉一个端口」，准确说法是「置为阻塞状态」。

5. 收敛：从环路到无环

端口从阻塞到转发，要按状态机一步步走：

状态行为停留时间
Blocking只收 BPDU，不学 MAC、不转发数据最长 Max Age（默认 20 秒）
Listening收发 BPDU，参与选举，仍不学 MAC 不转发Forward Delay（默认 15 秒）
Learning学 MAC 地址，仍不转发数据Forward Delay（默认 15 秒）
Forwarding正常转发—

所以经典 STP 的收敛要 30–50 秒——这就是「拔根网线，网络卡半分钟」的来源。

RSTP（Rapid Spanning Tree Protocol，快速生成树，IEEE 802.1w）做了两件事：端口角色增加了 Alternate（RP 的备份）和 Backup（DP 的备份），状态简化为 Discarding / Learning / Forwarding；靠 proposal/agreement 握手，备份端口切换不再傻等计时器，秒级完成。华为设备上 stp mode rstp 切换；较新的 VRP 版本默认 MSTP（stp mode mstp），它的快速收敛行为与 RSTP 一致。

7. eNSP 实验：亲手选一次 root

先搭好 eNSP 环境。eNSP 是华为官方免费模拟器（需华为账号下载），S5700 以本地进程运行，两台设备很轻量。环境搭建步骤见 lab/README.md；本课实验的详细步骤与预期输出见 lab/0001-stp-lab.md。下面的命令在 eNSP 里两台 S5700 上执行。 
# 拓扑：两台 S5700，用两条网线互连（GE0/0/1 连 GE0/0/1，GE0/0/2 连 GE0/0/2），成环

# 1. 等约 30 秒让 STP 收敛，看全局选举结果
display stp brief
#    两行关键信息：CIST Root 的 ID（谁是 root）、每个端口的 Role

# 2. 看单端口的详细状态（确认阻塞端口在收 BPDU）
display stp interface GigabitEthernet0/0/1

# 3. 改优先级，让另一台当 root（在要当 root 的那台上执行）
stp priority 4096
#    回到另一台再 display stp brief：root 换人，端口角色全部重排

# 4. 切 RSTP，再拔线计时恢复速度
stp mode rstp
#    拔掉一条线再插回，对比经典 STP 的 30–50 秒

# 5. 抓包看 BPDU：拓扑图上右键点一条链路 → 开始抓包，Wireshark 自动打开
#    每 2 秒一个 BPDU，对照第 2 节的字段表看 Root ID / Root Path Cost / Bridge ID

要观察的三件事：

  1. display stp brief 里哪台是 CIST Root、哪个端口是 ALTE（阻塞）——和第 6 节图里的手算结果对照；
  2. 改 stp priority 后，root 换人、所有端口角色重排——这就是「比小不比大」；
  3. Wireshark 里 BPDU 每 2 秒一个，拔线后能抓到 TCN BPDU——STP 的「心跳」和「报警」。
注意：如果 display stp brief 显示协议状态为 disabled，先在系统视图执行 stp enable。VRP 较新版本默认已启用，且默认 MSTP 模式——本课实验建议先 stp mode stp 切经典模式观察状态机，再切 stp mode rstp 对比收敛速度。命令语法以设备自带 ? 帮助为准。
